# 小青蛙聚合发布集成

本文定义平台与 Apifox“小青蛙APi”项目中聚合发布能力的调用边界、渠道缓存、投稿和状态映射；平台自己的余额、权限与订单状态仍以本地领域规则为准。

## 配置与上游接口

平台管理员在 `/admin?section=publications` 的“小青蛙 API 接入设置”中填写基础地址和 API Key。`PUT /v1/admin/publication-provider-configuration` 保存前并行验证 `/api/geo/get_balance`，以及网站媒体与自媒体的 `media_list`、`get_field`、`order_info` 七类安全读取能力；订单查询使用不存在的探测 ID，不创建投稿或改变订单。任一接口拒绝或响应不符合契约时都不写入配置。全部通过后使用 `APP_ENCRYPTION_KEY` 和固定平台 AAD 做 AES-256-GCM 加密，保存到单例表 `platform_frog_credentials`；读取接口只返回 Key 掩码、版本、来源与健康时间。Web 与 Worker 每次执行聚合发布业务时从同一数据库配置解析客户端，因此保存或轮换后无需分别修改容器环境变量。

`FROG_PUBLICATION_BASE_URL` 和 `FROG_PUBLICATION_API_KEY` 仅作为旧部署兼容回退：数据库尚无网页配置时继续生效，网页保存后由数据库配置优先。默认基础地址为 Apifox 当前接口定义中的 `http://8.138.187.158:8082`。完整 Key 不进入浏览器读取响应、日志或明文数据库字段。没有数据库配置且环境 Key 为空时，租户端只显示人工发布渠道并跳过上游同步；任一种来源有效时只显示聚合渠道。服务端在扣款前再次拒绝未配置 Key 的聚合渠道请求。

当前接入两组等价资源：

| 媒体类型 | 路径前缀            | 用途                                           |
| -------- | ------------------- | ---------------------------------------------- |
| 网站媒体 | `/api/media`        | 媒体列表、媒体分类、投稿、订单详情、取消和申诉 |
| 自媒体   | `/api/zi_media_api` | 媒体列表、媒体分类、投稿、订单详情、取消和申诉 |

所有上游请求使用 `multipart/form-data`，并在表单中传递 `api_key`。成功 envelope 为 `code = 1`；HTTP 异常、非法 envelope、业务拒绝和超时分别归一化，不向客户端透传 Key 或完整正文；业务拒绝使用固定错误文案，请求禁止跟随重定向。订单和资源 ID 保留字符串精度，不接受已超出安全整数范围的数值 ID；发布结果链接仅接受 HTTP(S)。

平台管理端通过 `/api/geo/get_balance` 读取小青蛙账户的 `money` 发布余额和 `power_count` 接口算力，并在“发布履约”页展示连接状态与最近核对时间。该余额属于平台共用的上游采购账户，不等同于租户品牌的 `publication_cny` 本地余额，也不向租户端暴露。聚合投稿会在本地扣款前执行余额预检，明确不足时停止创建订单；预检查询失败不把未知状态误判为不足，仍由 `send` 作最终校验。管理页查询失败只把上游余额标记为暂不可用，不阻断本地渠道与订单管理。

## 渠道缓存与定价

读取有效发布渠道时，页面请求只分页读取 `publication_channels` 本地缓存并立即返回，翻页、搜索或排序都不会调用小青蛙目录接口。首次保存或轮换 Key 时启动一次后台同步；此后 Worker 复用每 5 分钟执行的聚合发布维护任务检查目录时间戳，只有最近一次渠道更新时间超过 30 分钟，或 Key 配置比渠道缓存更新时，才分别分页调用两类 `media_list`。同步遵守生产接口每页 `1–100` 条的限制，以每页 100 条、每类最多 100 页读取并更新缓存，因此多次打开页面不会重复抓取上游。同步还会调用 `get_field`，兼容生产响应中超出 Apifox 描述范围的 `field_10`、`field_11` 分类类型，并把媒体资源当前携带的 `field_1` 至 `field_9` 分类 ID 转换为可检索的行业和媒体属性标题。`provider = frog_media`，并以“provider + media type + resource id”唯一定位上游资源；名称、上游接单状态、采购成本、备注、案例、分类、权重、出稿率和平均发布时间随同步更新。平台上下架状态、客户等级规则和渠道固定售价是本地经营数据，上游目录刷新不得覆盖。

租户发布页以渠道库方式展示缓存结果，支持网站媒体、自媒体和人工渠道分类，按媒体名称、行业属性、发布要求、预算、当前用户等级售价、出稿率和平均出稿时间检索排序；筛选、排序和分页均在服务端缓存查询中完成，每次最多返回 100 条，选中后展示案例、媒体备注和履约指标。管理端渠道表同样使用服务端分页，并提供来源、媒体类型、平台状态、关键词和履约指标排序；每行同时展示采购成本、普通用户与金银铜代理售价、平台状态及上游状态。这样避免把约两万条目录和近 20 MB JSON 一次传入浏览器或创建数万行 DOM。页面只读取本地渠道缓存，API Key 不进入浏览器。

上游 `price` 为人民币元字符串，服务端使用十进制定点规则转换成人民币分并保存为 `provider_cost_amount`。客户售价由 `pricing_tier_rules` 的发布加价率计算，或由 `publication_channel_price_overrides` 的“渠道 + 等级”固定价覆盖；固定价不得低于聚合采购成本。创建订单时按操作用户的 `users.pricing_tier` 在数据库事务内重新计算人民币分价格并保存扣款快照，最大为 10 亿分。零元订单不生成零金额扣款或退款流水。读取上游失败时返回最近一次成功缓存，不删除人工渠道，也不把一次部分读取当作全量下架依据。

## 投稿与幂等

聚合发布投稿必须提供 HTML 正文，或提供当前企业、内部范围和品牌下已成功的文章生成任务 `sourceJobId`，或提供状态为 `ready` 的本地文档 `sourceDocumentId`；两个来源 ID 不能同时提交。服务端重新读取任务或文档正文并复核品牌范围，不信任浏览器转交的内容；直接提交的 HTML 只用于本次上游调用，不进入发布订单列表或持久化快照。

本地先在事务中按幂等键创建 `submitted` 订单并扣减品牌 `publication_cny`，再调用上游 `send`。本地订单 ID 作为 `third_id` 传递：

- 上游明确接受后保存 `order_nid`，本地进入 `processing`；
- 上游明确业务拒绝时本地进入 `failed` 并幂等返还余额；
- 超时、网络中断或 5xx 可能已经产生上游副作用，因此订单保留 `submitted`，返回 `FROG_PUBLICATION_RESULT_UNCERTAIN`，不得自动重复投稿或退款；
- 同一本地幂等键重放优先返回既有订单，即使渠道已下架或 Key 已移除也不再次投稿；同键但品牌、渠道、标题、操作用户、来源任务或来源链接不同则返回 `409 PUBLICATION_IDEMPOTENCY_CONFLICT`。

创建事务对“企业 + 幂等键”加 advisory lock，串行化并发重放。发布页对相同表单保留重试键并阻止双击提交；结果不确定时保留正文和来源任务/文档。直接 HTML 不持久化，因此当前幂等冲突检查不比较正文摘要；来源任务和来源文档 ID 都参与冲突检查。审计写入失败记录固定日志，不阻断已扣款订单的上游投稿。

## 状态同步、取消与申诉

Worker 启动后及每 5 分钟执行 `publication-reconciliation`，按最久未同步优先选取最多 100 条有上游订单号的待履约或售后订单，每类每批 20 条调用 `order_info`；无需浏览器保持打开。当前品牌订单列表读取也会触发同步，并接受 Apifox Schema 声明的数组形式以及示例中的单对象形式。状态映射如下：

| 上游状态   | 本地状态                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------- |
| `0` 待安排 | 确认上游已接收，进入 `processing`                                                        |
| `1` 已安排 | `processing`                                                                             |
| `2` 已发布 | 有结果链接时进入 `published`                                                             |
| `4` 已退稿 | 未发布订单进入 `failed` 并幂等返还余额；已发布申诉单仅在 `is_refund = 1` 时进入 `failed` |
| `9` 售后中 | 未发布订单为 `processing`，已发布订单保持 `published`                                    |

同步同时核对上游订单号与媒体资源 ID，并使用读取时的 `updatedAt` 作条件更新，迟到响应不覆盖较新状态。已发布申诉单在上游状态 `9` 或 `4` 且尚未退款时继续轮询；一批查询失败不阻止其余批次，后台任务通过稳定错误码报告部分失败。

取消仅允许 `submitted`、`processing`；已取消的重试直接返回原订单，已发布或失败订单在调用上游前返回冲突。取消聚合订单先调用上游 `cancel_order`，成功后本地进入 `cancelled` 并返还余额；上游拒绝时本地不伪造取消。申诉仅允许 `processing`、`published`；已有售后状态 `9` 时返回原订单。申诉调用 `rejection`，原因限定为 Apifox 契约的 `1`–`4`，成功后记录售后状态和说明，并继续查询已发布订单；只有上游明确标记已退款时才返还本地余额。人工渠道继续使用平台管理员履约流程；管理员手工状态更新入口拒绝聚合订单，避免跳过上游直接结单或退款。

结果不确定且尚未保存 `provider_order_id` 的订单不在自动同步候选中。当前上游契约没有按 `third_id` 反查的接入能力，仍需核对上游后台后处理，平台不自动猜测订单号、重投或退款。
