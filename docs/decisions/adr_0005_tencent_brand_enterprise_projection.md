# ADR-0005：腾讯品牌目录作为平台企业唯一来源

- 状态：accepted
- 日期：2026-09-13
- 决策范围：平台企业来源、腾讯品牌同步与内部租户投影
- 扩展：[ADR-0004](./adr_0004_direct_answerbit_operations.md)
- 后续扩展：[ADR-0006](./adr_0006_tencent_connection_readiness_gate.md)
- 后续扩展：[ADR-0009](./adr_0009_enterprise_brand_only_business_scope.md)

## 背景

固定 TeamID 下的腾讯 BrandID 已经是平台业务的上游资源边界，但原流程仍要求管理员先同步品牌，再填写名称、slug 和负责人创建一份本地企业并人工绑定。这会产生与腾讯目录无关的本地企业，也会让“腾讯目录”和“平台企业”出现不必要的中间状态。

平台仍需要 `organizations` 承载成员、RBAC、余额、业务数据、外键和 RLS，不能直接用上游 BrandID 替代内部租户主键。因此需要把本地企业从独立创建的业务资源改为腾讯品牌的内部投影。

## 决策

1. 固定 TeamID 的腾讯品牌目录是平台企业的唯一来源。一个 Tencent BrandID 对应一个内部 `organization`，BrandID 与 organization 均保持一对一唯一约束。
2. 保存统一配置或通过 `/geo/brand/create` 新建腾讯品牌时，系统自动创建缺失的企业投影；平台企业的日常增删改以腾讯品牌写接口为主路径。
3. 自动创建使用 BrandID 的 SHA-256 摘要生成稳定内部 slug，并同时创建固定 TeamID 绑定、托管连接占位、品牌映射和默认资源权益。
4. 触发首次投影的 `super_admin` 作为初始 `tenant_admin`，随后可在企业详情中增加或转移管理员与成员权限。
5. `/admin` 企业目录、团队目录、总览统计和租户可见企业只包含存在 Tencent BrandID 映射的投影。历史未映射本地企业不再进入正常产品路径。
6. 本地企业创建、企业名称修改和历史企业手工绑定接口均返回 410，不在管理界面展示。
7. 平台企业修改先调用腾讯 `/geo/brand/update`，成功后更新品牌目录、品牌映射和企业投影名称；上游失败时本地不提交修改。
8. 平台企业删除先调用腾讯 `/geo/brand/delete`，成功后把内部 organization 标记为 `closed` 并停用其团队绑定和连接。目录项与一对一映射作为删除标记保留，防止后续目录核对重新创建企业，同时保留历史业务、计费和审计关系。
9. Worker 每 5 分钟自动读取一次固定 TeamID 的完整品牌目录；腾讯控制台直接新增或改名的品牌自动进入平台，已投影品牌连续两次核对缺失后才关闭。自动任务与平台写入通过 advisory lock 和 Key 版本校验串行化，不恢复已经关闭的投影。

## 取舍

该模型消除本地企业与腾讯目录漂移，平台管理员只需要维护统一凭证，并优先通过平台企业界面直接操作腾讯品牌。已有目录导入并入统一配置保存流程；后台自动核对负责接收腾讯控制台产生的目录变化，ADR-0007 另外恢复一个复用相同编排的立即同步入口。代价是企业显示名称不能独立于腾讯品牌命名，且配置操作者或有效平台管理员会暂时成为自动发现企业的管理员。

内部 `organizations` 不代表另一套可独立创建的企业目录。它是 Tencent BrandID 在本平台的租户、安全、计费和数据隔离投影，仍需保留独立 UUID，避免把外部标识直接作为所有本地关系的主键。

## 后果

- 已导入但尚未投影的腾讯品牌会在下一次配置保存、Key 轮换或最长约 5 分钟后的周期核对中自动生成企业。
- 腾讯品牌创建成功后，响应同时返回对应 `organizationId` 和 `organizationName`。
- 腾讯企业修改和删除只有在上游成功后才改变本地投影；已删除投影不出现在平台或租户列表，也不会被后续配置验证重新激活。
- 未映射历史企业数据仍保留在数据库供审计或离线迁移处理，但不出现在正常平台和租户目录，也不能通过产品 API 重新绑定。
- `platform_answerbit_brands.missing_sync_count` 记录连续目录缺失次数，用于在自动关闭与短暂上游异常之间建立安全边界。
