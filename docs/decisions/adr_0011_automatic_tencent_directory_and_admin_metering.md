# ADR-0011：腾讯目录后台同步与平台计量中心

- 状态：accepted（扩容部分已由 [ADR-0012](./adr_0012_official_tencent_quota_purchase.md) 替代）
- 日期：2026-09-17
- 决策范围：腾讯企业目录同步入口、平台计量可见性与官方扩容入口
- 替代：[ADR-0007](./adr_0007_manual_tencent_enterprise_sync.md) 的平台页面手动同步入口

## 背景

Worker 已能在启动时和每 5 分钟核对一次腾讯品牌目录，但平台“腾讯企业”仍把“立即同步”作为显著操作，导致管理员把正常一致性误解为需要反复手工触发。本地开发原本只启动 Web，也会使自动任务未运行而强化这种误解。

平台已经接入腾讯计量中心的九个只读 OpenAPI，但完整订阅、积分批次、订阅日志和配额调整只出现在客户工作台路径，平台控制面缺少统一入口。腾讯公开 OpenAPI 当前只提供计量读取，不提供积分扩容写接口，因此平台不能伪造成功扣减或维护一份与腾讯不一致的积分账本。

## 决策

1. Worker 启动时立即执行目录核对，之后每 5 分钟自动同步；这是产品内的默认一致性机制。平台“腾讯企业”页面每 60 秒刷新本地投影，并在页面重新可见或恢复联网时补拉，不再展示手动同步按钮。
2. `POST /v1/admin/answerbit-enterprise-syncs` 保留为运维诊断和兼容资源，不作为日常管理页面入口；它继续复用自动任务的锁、Key 版本和连续缺失规则。
3. 根命令 `pnpm dev` 同时启动 Web 与 Worker，确保本地开发默认具备目录同步和其他周期任务；只调试同步 Web 时使用 `pnpm dev:web`。
4. 平台管理新增“腾讯计量”模块，读取固定 TeamID 的订阅、积分、周期配额、趋势、品牌排行、积分流水、订阅日志和配额调整。平台管理员可跨企业选择腾讯品牌范围，但服务端仍验证企业、内部绑定与 BrandID 映射。
5. 计量模块提供“用积分扩容 · 监控品牌”估算卡：单次数量为 1–9999，当前展示单价为每个 400 积分，预计余额使用腾讯积分状态实时计算。原决策要求进入腾讯控制台完成确认；该交互已由 ADR-0012 替代为平台服务端直接调用腾讯官方增购接口。
6. 计量页每 60 秒自动刷新，并在从腾讯控制台返回或恢复联网时立即补拉，因此扩容和计量变化不依赖管理员再次点击目录同步。

## 取舍

移除日常手动按钮后，腾讯控制台产生的品牌变化最多需要一个 Worker 周期和一个页面刷新周期进入当前视图；运维端点仍可用于明确的故障核对。默认同时启动 Worker 会增加一个本地进程和数据库连接池，但换来与生产一致的自动任务行为。

扩容操作仍在腾讯官方控制台完成，无法做到平台内单击即扣减；好处是不依赖未公开接口、不重复记账，也不会向管理员显示并未发生的积分消费。若腾讯以后发布受支持的扩容写接口，应另建决策并以服务端响应和积分流水作为成功依据。

## 后果

- 管理员日常只管理腾讯企业资源，目录新增、改名和关闭由后台任务自动进入平台；
- 本地执行 `pnpm dev` 后，“运行与审计”应看到 Worker 心跳及腾讯企业同步任务状态；
- `/admin?section=metering` 成为共享 TeamID 计量数据的管理入口，普通企业用户仍只看到本企业品牌范围；
- 手工同步 API 和审计语义继续保留，但 UI 与操作手册不再把它作为首选恢复动作；
- 扩容估算、直接提交与结果确认的当前规则见 ADR-0012。
