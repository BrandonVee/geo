# ADR-0015：按客户等级对功能基础积分加价

- 状态：accepted
- 日期：2026-09-27
- 决策范围：功能积分的等级价格计算，替代 [ADR-0014](./adr_0014_user_pricing_tiers_and_channel_margin.md) 的积分系数规则；发布售价和客户等级规则继续有效。

## 背景

原规则把等级值当作基础积分的乘数，普通用户 100%、铜牌 90%、银牌 80%、金牌 70%，在管理页面与发布采购成本加价率并列时含义不一致。平台需要以统一的加价百分比表达两类定价，同时仍允许分别调整发布和积分价格。

## 决策

1. `feature_point_costs.points` 是功能基础积分，`pricing_tier_rules.point_markup_bps` 是独立的等级积分加价率；实际积分按 `ceil(基础积分 × (10000 + 加价基点) / 10000)` 计算。
2. 新规则的普通用户、铜牌、银牌和金牌初始积分加价率为 30%、20%、15%、10%，与发布加价率的初始值相同；之后两项独立配置，0% 表示按基础积分计费。
3. v6 迁移把未修改的旧等级积分系数换成该等级当时的发布加价率；已由管理员修改的等级规则把旧系数减去 100% 转为等效加价率，允许最低 -100%，以保留原实际扣费与自定义折扣。
4. 管理员调整基础价或等级加价率后，新提交的操作立即采用新价格；用户提交计费操作时附上已看到的积分报价，服务端复核不一致则返回 `409 FEATURE_PRICE_CHANGED` 且不扣费或调用上游。新建异步文章任务保存等级、基础积分、加价率和最终积分的价格快照，Worker 按快照扣费；升级前没有快照的任务按执行时规则计价。
5. 历史积分流水保持原扣减与返还金额，不追溯重算。当前效果追踪基础价为 2 积分，默认四档实扣均为 3 积分，接受这一结果，不为了人为区分等级而提高基础价。

## 后果

- 基础 100 积分在 30% 加价下扣 130 积分，向上取整仍只发生一次。
- 管理页面、API、审计和数据库使用“积分加价率”语义，不再把 100% 解释为无变化。
- 旧自定义折扣以负加价率呈现，升级不改变其有效扣费；页面明确提示负值表示折扣。
- 提交后修改价格等级或基础价不会改变已创建文章任务的锁定金额，失败返还仍按原扣款金额执行。
