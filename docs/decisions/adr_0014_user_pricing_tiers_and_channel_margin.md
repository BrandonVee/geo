# ADR-0014：按用户价格等级计算发布售价与功能积分

- 状态：accepted
- 日期：2026-09-19
- 决策范围：代理商分级、发布利润与功能积分差异化计费

## 背景

小青蛙目录中的 `price` 是平台采购成本，不应直接作为所有客户的最终售价。平台需要在持续同步约两万条上游媒体的同时保留自己的利润规则、人工上下架和单渠道调价；普通用户与金银铜代理也需要不同的发布售价和功能积分成本。

把最终售价直接写回上游同步字段会在下一次目录刷新时丢失经营配置；为每个渠道永久写四个派生价格，又会使全局加价规则调整必须批量更新全部目录。

## 决策

1. `users.pricing_tier` 使用 `retail`、`bronze`、`silver`、`gold`；客户和管理员固定为 `retail`，代理商选择金银铜等级；
2. `pricing_tier_rules` 保存每级发布加价基点和功能积分计费系数，默认分别为普通用户 30%/100%、铜牌 20%/90%、银牌 15%/80%、金牌 10%/70%；
3. `publication_channels.provider_cost_amount` 与 `provider_status` 只保存上游采购成本和接单状态，原 `status` 继续作为平台上下架状态；
4. `publication_channel_price_overrides` 只保存确有需要的“渠道 + 等级”固定售价；无覆盖时动态按等级加价规则计算，聚合渠道固定售价不得低于采购成本；
5. 渠道列表按当前操作用户等级在服务端筛选、排序和返回价格；创建订单在扣款事务中重新计算并写入订单价格快照；
6. 上游余额预检比较采购成本，品牌人民币余额扣减客户售价；两者差额是平台毛利，不建立第三种余额资产；
7. 完整业务功能继续按 ADR-0010 只结算一次，但实际积分为基础积分乘用户等级系数并向上取整。

## 后果

- 上游目录刷新可以安全更新成本和接单状态，不覆盖平台售价或上下架；
- 管理员可统一调整四级利润，也可覆盖单个渠道价格；
- 同一渠道对不同用户返回不同售价，历史订单和退款始终使用下单时快照；
- 用户价格等级变化只影响之后的新订单和新功能结算，不追溯修改历史流水；
- 客户价格等级不是权限或余额额度，仍需通过既有 RBAC、品牌范围和双余额校验。
