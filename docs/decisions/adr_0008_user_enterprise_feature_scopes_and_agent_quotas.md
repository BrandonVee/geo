# ADR-0008：按企业收窄用户功能并设置代理商经营额度

## 状态

已接受，2026-09-13。

## 背景

企业角色和品牌角色适合表达通用职责，但同一用户在不同企业可能只获准使用部分产品模块。代理商还需要由平台限制其可管理企业数、品牌创建数和腾讯积分划拨量。把这些差异继续拆成大量角色会造成角色爆炸，也难以在用户编辑界面统一维护。

## 决策

1. 保留现有 RBAC 作为权限上限，新增 `organization_user_feature_scopes`，按用户和目标企业保存固定功能模块 allowlist。
2. 没有显式范围记录时继承角色默认能力；有记录时与角色权限取交集；空数组表示关闭目标企业全部业务模块。功能范围不产生提权。
3. 在 `users` 保存代理商企业、品牌和腾讯积分三个可空非负上限。`null` 表示不限，`0` 表示禁止。
4. 企业额度在平台分配 `tenant_admin` 时校验；品牌额度在品牌创建前校验；腾讯积分额度在余额划拨事务中通过用户行锁校验。
5. 用户详情返回显式功能范围和当前额度用量，平台管理员通过同一用户编辑动作更新账户类型、有效期、额度与全部目标企业范围。

## 后果

- 权限判断增加一层数据库读取，但所有业务入口获得一致的逐企业模块限制；
- 角色、功能范围、品牌范围、企业权益与余额必须全部满足，UI 仅展示结果而不是授权边界；
- 降低额度不会改写历史操作，只会阻止后续增量；
- 新增企业业务权限时必须补充其所属功能模块，否则核心映射测试和文档审计应阻止遗漏。
