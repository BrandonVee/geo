# ADR-0001：采用人工双余额账本

- 状态：accepted
- 日期：2026-09-10
- 决策范围：平台资金与资源计量

## 背景

早期方案包含套餐购买、在线充值、订单支付、微信支付回调与对账。当前业务要求平台不处理在线收款：资金由平台管理员或代理商按组织和品牌运营关系人工划分。同时，腾讯 AnswerBit 能力调用与媒体发布的单位、成本来源、退款时机和权限责任不同。

## 决策

1. 删除客户在线充值、支付收单、支付回调和支付对账功能；
2. 建立两个独立资产：`answerbit_points`（整数积分）与 `publication_cny`（人民币分）；
3. 平台管理员只向企业资金池人工入账；企业管理员或代理商只把企业余额划分到品牌；
4. 腾讯能力按完整业务功能预扣积分，AnswerBit operation 调用本身不计费；失败使用幂等补偿流水返还；
5. 发布单按渠道人民币价格快照扣减，失败或取消时返还原品牌；
6. 平台内部 entitlement 继续限制成员、团队、品牌、文章与报告等资源，但不表示付款或订单。

## 取舍

采用两个账本增加了资产类型、流水和管理页面数量，但避免把不可兑换的积分与法币混在一起，也使腾讯调用失败补偿和发布履约退款拥有独立审计链。

人工入账降低了支付系统、合规、回调安全和对账复杂度，但要求运营人员执行额度分配，并依赖审计日志和幂等键控制误操作。

## 后果

- 产品界面和 API 不出现充值、支付方式、支付订单或收款状态；
- 金额始终以整数最小单位存储，前端只负责格式化；
- 企业资金池与品牌账户之间的每次变动必须有不可变流水；
- 上游 subscription/credit 只用于展示 AnswerBit 状态，不能替代本平台积分余额；
- 将来若引入在线收款，必须新建 ADR，明确资金许可、支付提供方、订单状态机、回调验签、对账和迁移策略。

## 替代的历史方案

本决策替代历史需求和技术设计中的在线套餐购买、微信支付和自动充值方案。历史材料保留在 [归档目录](../archive/index.md)，不再作为当前实现依据。
