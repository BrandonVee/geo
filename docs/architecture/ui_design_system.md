# 企业级 UI 设计系统

本文定义 AnswerBit GEO Web 的统一视觉语言与交互基线，适用于登录、租户工作台和平台管理端。组件实现以 Ant Design 5 为唯一权威：Next.js App Router 入口在 `layout.tsx` 使用 `@ant-design/nextjs-registry` 的 `AntdRegistry` 注入首屏样式，`providers.tsx` 只负责中文 `ConfigProvider` 与 `App` 上下文。业务页面不得复制控件样式、覆盖 `.ant-*` 内部选择器或重新建立页面级组件皮肤。

## 设计方向

采用轻量、克制且数据优先的企业 SaaS 方向，并继续以 Ant Design 组件和 Design Token 实现：默认使用浅色界面、靛蓝主色与中性工作表面，渐变仅允许用于公共入口的低强度背景，不用于工作台字标、头像、数据容器或业务状态。浅色主题的主色使用满足白色按钮文字对比度要求的 `#4f46e5`。租户工作台桌面端使用 248px 左侧导航和占满剩余宽度的内容画布；平台管理因资源分组更多可继续使用 280px 侧栏。侧栏外层使用 12px 留白，内层白色面板使用 10px 圆角且不使用装饰性阴影。全局导航使用 `Layout`、`Sider`、`Header`、`Menu`，页面内容使用 `Card`、`Table`、`List`、`Descriptions` 和 `Statistic`。

公共首页和登录页必须优先建立企业产品可信度：首页首屏同时呈现明确业务价值、真实工作台形态和“分析 → 生成 → 发布”闭环，不使用无法核实的宣传型伪指标；登录页的品牌说明区不得超过桌面可用宽度的约 40%，表单仍是页面主任务。工作台首屏以数据、筛选、表格和操作为主要内容，说明与装饰不应成为独立的大面积区域。

## 字体层级

全站使用 Ant Design 默认字体栈。字号通过 `Typography` 与组件 Token 生成，仅使用以下语义层级：

| Token         | 字号    | 用途                                           |
| ------------- | ------- | ---------------------------------------------- |
| Display       | 38–62px | 公共首页主标题；业务工作台不使用               |
| Page title    | 28–30px | 页面唯一 H1                                    |
| Section title | 16–18px | 卡片、表格或业务区块标题                       |
| Subheading    | 15–16px | 行标题、弹层小节                               |
| Body          | 14–15px | 正文、菜单、表格、输入内容、主要按钮           |
| Label         | 13–14px | 表单标签、次要按钮、说明文字                   |
| Caption       | 12–13px | 时间、状态、眉题、辅助元数据；这是可见文本下限 |

标题行高 1.2–1.3，正文行高 1.5–1.6。业务正文不使用全大写；英文眉题可使用 0.12em 字距。

## 颜色与表面

颜色与表面统一读取 Ant Design Alias Token，例如 `colorPrimary`、`colorText`、`colorTextSecondary`、`colorBgLayout`、`colorBgContainer`、`colorBorderSecondary`。浅色主题主色为 `#4f46e5`，页面底色为 `#f8f9fb`，容器为白色；深色主题保留为用户主动选择的辅助模式。业务代码不得在局部重新指定另一套主色、圆角或阴影。状态必须使用 `Alert`、`Badge`、`Tag` 或 `Result` 的语义属性，颜色不能成为唯一信号。正文、辅助文字、占位文字、状态标签及按钮文字与背景的对比度遵守 WCAG AA：常规文本至少 4.5:1，大号文本至少 3:1。

## 间距与布局

间距采用 4px 基准，常用值为 8、12、16、20、24、32、40、48、64。工作台与平台管理主内容区均占满侧栏之外的可用宽度，不再设置 1400px 上限或 600px 最小宽度。桌面页面横向内边距 20–32px，移动端为 12–16px。正文、表单等需要控制阅读长度的局部内容可单独设置最大宽度，但表格、统计卡片和业务面板不得因此收缩到左侧。

- 输入、选择等表单控件保持 40–44px；常规按钮使用 32–36px 的紧凑高度，避免工具栏和表格操作过重；
- 卡片内边距 16–24px，业务区块间距 16–20px；同一业务区不要为每个小指标或步骤重复套卡片，一级容器内优先使用分隔线、行和表格建立层级；
- 每页只有一个 H1；核心数据摘要固定放在页面内容顶部，面向列表的筛选与主列表必须放在同一卡片或相邻卡片中，二者之间不插入统计摘要、导出工具或说明卡片；导出、保存视图等辅助工具放到主列表之后；
- 数据优先：主列表、订单和高密度记录优先获得主要宽度。依附于目录或列表的新增、编辑操作统一从对应卡片工具栏或行内操作进入 `Modal`/`Drawer`，不得以常驻表单挤占首屏；只有 AI 生成、媒体投稿等本身就是页面主任务的创建流程可常驻。全宽画布不等于所有区块单列：职责相关、字段密度匹配且可同时对照的只读模块可按主次使用 `16/8`、`14/10` 或 `15/9` 左右分栏；高密度表格、流程上下游或窄屏则顺序堆叠。
- 表格和列表保留可扫描行距，不用 12px 以下文字压缩密度；
- GEO 主流程在侧栏按“分析 → 生成 → 发布”分组展示，并保持企业与品牌上下文一致；内部腾讯范围由企业自动解析，不作为筛选项。

分析洞察首页固定采用“三项核心指标 → 自动侦察范围 → 分页工作区”的信息层级。系统默认读取首个可用企业与品牌的近 30 天数据，范围变化后自动重算，不要求用户先提交筛选条件；范围控件在桌面端保持单行紧凑排列，下拉框、日期框和查询按钮统一为 36px 高度，控件标签、卡片标题、说明文字与数据值使用稳定的 13/16/28px 层级，在中小视口改为两列，并提供近 7、30、90、180 天快捷范围和任意历史起止日期选择，未来日期不可选，“重新查询”只用于主动刷新。三项核心指标始终保留横向对比，不拆成三张纵向卡片。分页工作区使用“趋势洞察 / 竞品管理 / 增长行动”三个标签：趋势洞察先展示侦察样本、有效监测天数、竞争对象和模型范围，再用独立卡片从提及率、曝光效果、平均排名、任务样本量和竞争位次五个角度分析；全部趋势按日期升序绘制，左侧为最早日期、右侧为最新日期，不依赖上游数组顺序；排行超过 5 条分页。竞品目录支持名称或别名搜索、排序以及 5/10/20 条分页，并在小屏隐藏别名等次要信息，行内操作仅保留带可访问名称的图标；增长行动根据本期指标给出一个优先判断，并以紧凑操作行引导到问题、回答证据和内容生成，不使用三张说明型卡片重复讲解业务流程。页面显示本次数据更新时间，切换企业或品牌时清除旧指标、搜索条件和查询时间。

监控问题库使用“指标摘要 → 紧凑筛选与请求状态 → 全宽监控问题表 → 问题分类”的顺序。筛选与表格相邻，二者之间只允许放置与当前请求直接相关的错误或操作结果，不插入统计卡片。问题不再默认折叠在分类中；表格直接呈现问题、标签、全部监测模型、所属分类、启停状态、提及率、平均排名、提及变化和行内操作；问题的监测模型来自当前 TeamID 的完整平台目录，不随页面模型筛选改变，并必须复用集中映射，以中文名称和品牌图标展示，不直接暴露 `ideepseek`、`qianwen`、`yuanbao` 等平台标识。筛选区包含模型、问题分类、监测日期和关键词，模型选择只改变本次指标查询范围。页面不展示最近同步、下次同步、自动同步开关或刷新频率；首次进入、范围/筛选/分页变化和用户点击刷新时直接发起最新数据请求。分页与跨页选择保持服务端语义；问题和分类的新增入口放在各自列表工具栏，新增与编辑统一使用宽版 `Modal`，成功后关闭并刷新，失败时保留输入。移动端只允许表格区域横向滚动，不让页面整体溢出。回答与引用页同样先展示核心统计，再连续展示筛选和回答列表，保存视图与导出工具移到列表之后。

模型筛选在数据总览、监控问题、回答与引用等使用 AnswerBit 平台维度的页面保持一致：统一使用可搜索多选，选项值继续使用腾讯返回的平台标识，请求参数继续使用 `platforms` 数组语义；问题分类等天然可组合的筛选同样使用多选，并通过响应式标签折叠避免挤压工具栏。展示层集中映射为用户可识别的中文模型名称，并在选择器、当前筛选和含模型字段的列表/详情中使用对应品牌 SVG 图标。未知标识回退到上游名称与通用模型图标，不在各页面复制映射。

## 组件规则

- 所有交互控件使用 Ant Design；禁止新增原生 `button`、`input`、`select`、`textarea` 作为业务控件；
- 表单统一使用 `Form`、`Input`、`InputNumber`、`Select`、`Checkbox`、`DatePicker`、`Button`；
- 列表和明细统一使用 `Table`、`List`、`Descriptions`，分页使用 `Pagination`；
- 对话交互使用 `Modal`、`Drawer`、`Popconfirm`，禁止 `window.prompt` 和 `window.confirm`；
- 主按钮每个操作区最多一个，危险操作必须标红并二次确认；
- 会扣减平台积分的业务继续由服务端按当前用户等级结算，表单主按钮使用“提交生成 · 消耗 N 积分”“加入追踪 · 消耗 N 积分”等直接动作名称并展示当前有效价格；操作前页面不额外常驻“预计消耗 N 积分”“失败自动返还”或工作流说明类静态 `Alert`。余额不足、请求失败等真实状态仍按错误语义即时反馈；用户主动点击具有独立外部副作用的确认操作后，二次确认层仍可说明本次实际影响；
- 卡片只承载一个清晰主题，标题、操作和状态位置保持一致；
- 空状态说明缺少什么以及下一步入口，加载态保留布局尺寸；
- 成功、警告和错误统一使用 Alert/Message 语义，不把服务端异常直接渲染为原始堆栈；
- 异步操作进入 loading 后禁用重复提交，完成后给出结果和下一步。
- `Progress` 必须按业务含义提供可访问名称；横向滚动表格必须包含键盘可聚焦内容，确保仅使用键盘也能进入并操作滚动区域；
- 必填字段在可见标签中明确标识并保留表单校验，不得把 `aria-required` 等属性挂到无语义的组件外层；带文字的 `Switch` 使用外部可见标签，避免未选中轨道上的低对比度微型文字；
- 图片上传统一使用 `Upload.Dragger`：在投递区明确格式与大小限制，选择后显示文件名、格式、体积和移除操作；客户端在提交前校验 MIME/扩展名与体积，API 边界再次校验 Base64、原始字节数和文件签名。服务端失败继续保留弹层和已选文件，只有用户确认提交后才产生远端写入。
- 受控 `Form.useForm` 实例只能在对应 `Form` 已挂载后读取、写入或监听；Modal/Drawer 的表单应在打开后的 effect 中回填，或使用 `forceRender` 保持连接，禁止对尚未渲染及已销毁的表单调用 `setFieldsValue`、`resetFields` 或 `useWatch`。

## 系统设置工作区

系统设置直接采用 Ant Design 标准信息架构，不维护页面专属视觉系统。页面骨架由 `Breadcrumb`、`Card`、`Flex`、`Select` 和 `Tabs` 组成；摘要使用 `Statistic`，引导使用 `Alert`/`Steps`，明细使用 `Table`/`Descriptions`，编辑流程统一使用 `Modal`/`Form`。企业选择写入 `organizationId` 查询参数，切换模块时保留该范围；只向 `tenant_admin` 展示可管理企业，其他角色进入设置页时使用 `Result` 呈现权限说明。

平台管理采用强制顺序“配置固定 TeamID 与统一 Key → 腾讯验证并导入已有品牌 → 开放平台模块 → 在企业与品牌页直连增删改”。未接入时自动进入“腾讯服务”，导航只开放该模块，客户工作台入口保持禁用；成功后才展示全局统计并开放客户经营、业务运营和系统治理。腾讯服务页显示统一配置、接入状态及进入企业与品牌页的下一步，密钥使用密码输入框录入且永不回显明文。“企业与品牌”页的新增、编辑弹窗明确标记真实上游写入，删除使用 `Popconfirm` 说明先删除腾讯品牌、再关闭本地投影，按钮在请求期间进入 loading，且只在腾讯成功后更新平台。企业目录由 Worker 自动同步且页面自动刷新，不展示日常手动同步按钮。“腾讯用量”的监控品牌扩容卡展示数量、预计积分和预计余额，点击“确认扩容”后再次确认真实腾讯积分副作用；提交期间按钮 loading，腾讯成功后显示成功提示并自动刷新配额、积分和记录。页面不提供本地创建、团队管理和手工绑定表单。租户腾讯设置页只读展示统一接入和本企业品牌健康，不展示 TeamID、内部绑定或团队操作。错误在当前工作区保留并提供重试，不以成功的本地 HTTP 状态冒充上游就绪。

平台管理资源中心使用 `section` 查询参数保存当前模块，菜单切换保持 SPA 导航并支持深链接和浏览器历史。客户与代理管理遵循“账户摘要 → 客户等级与利润策略 → 检索与筛选 → 用户目录 → 档案抽屉”的层级；创建账户放入独立 `Modal`，停用账户必须使用 `Popconfirm`，账户类型、平台角色、企业关系与品牌范围不得压缩在同一状态字段中。客户与代理商切换及代理商有效期设置使用独立编辑 `Modal`；有效期提供“长期有效”和“指定时间范围”，列表与档案明确区分正常、未生效、已过期和已停用。

平台管理外壳与租户工作台共享 Answerbit 视觉语言，但保持全局控制面的独立信息架构：桌面端使用 280px 圆角侧栏，按“总览 / 服务接入 / 客户经营 / 业务运营 / 系统治理”分组资源导航，并将当前管理员与主题、工作台返回、刷新入口收纳到侧栏底部；内容区按当前 `section` 展示独立页面标题与说明，并继续占满可用宽度承载高密度表格。运营总览采用“核心指标 → 接入与账户结构 → 最近审计与调用”的层级；资源列表先提供服务端搜索和状态筛选，再展示表格。小于 992px 时切换为 60px 顶栏和同构抽屉导航，不保留一个不可见的折叠侧栏。

资产与计费模块在宽屏把入账对象与积分规则目录按 `14/10` 并排，用户流水保持全宽，积分规则新增/编辑表单放在目录之后，服务端分页并支持按企业、操作用户、资产及操作类型筛选。租户端资产划拨使用独立 `/dashboard/balances` 工作区，只向至少在一家企业拥有 `balance.allocate` 角色能力的用户显示导航；页面展示企业资金池、当前品牌账户、划拨表单和企业资产流水。发布页不读取企业资金池、不展示划拨表单或资产流水。空操作用户统一显示为系统任务或历史记录，不臆造用户身份。

租户“积分用量”展示本系统当前用户有权访问的企业/品牌积分，不展示共享 TeamID 的腾讯订阅、积分批次或上游额度。页面采用“品牌可用积分、企业可分配积分（仅企业管理员）、周期消耗、失败返还 → 企业/品牌/日期/类型筛选 → 消耗明细”的紧凑层级；筛选和表格在同一卡片相邻呈现，明细以正负号、中文类型、业务说明、操作用户和变动后余额表达本地账本事实。平台管理继续以独立“腾讯计量”模块跨企业选择品牌范围，并按腾讯官方口径展示共享 TeamID 的订阅、积分批次、消耗、日志和配额调整。平台管理员还可用“用积分扩容 · 监控品牌”卡先查看当前容量上限、已创建品牌、当前可用配额和使用率，再输入 1–9999 的数量并预览扩容后容量、按每个 400 积分计算的预计消耗与余额，经二次确认后直接提交腾讯官方增购接口；页面不在未获得官方成功响应时显示已扩容，并在成功后自动刷新积分、配额和记录。平台余额页只维护业务功能积分规则，不展示或划分品牌套餐；页面明确说明接口调用为 0 积分，同一完整功能只结算一次。

成员权限页直接展示成员统计和可检索目录，不使用通用权限模型提示占用首屏。添加品牌角色时由系统自动使用当前企业唯一 Tencent BrandID，不显示团队选择器，也不要求管理员手工输入 BrandID；企业管理员直接获得企业范围。配置权限、停用/恢复和移出企业均为表格行内直接操作，不折叠到更多菜单；危险操作继续使用二次确认。

编辑弹层使用宽版布局：简单单字段弹层不小于 600px，多字段表单以 720–760px 为基线，权限与额度等复杂编辑可扩展到 1080px；移动端由 Ant Design 自动限制在视口内。输入和选择控件采用 large 尺寸，按钮单独使用紧凑规格；弹层表单显式继承 large 尺寸。受控 Form 在弹层打开后的 effect 中回填，避免未连接表单和服务端 Portal 警告。

AI 内容生成保持一个顶层导航入口，因为生成、文档管理和发布效果追踪共享同一企业与品牌范围，但在页面内明确拆成“AI 生成 / 文档库 / 效果追踪”三个可深链接标签。默认进入 AI 生成，并按 `16/8` 展示生成表单和最近任务；文档库按 `5/19` 使用左侧目录和右侧全宽文档表，支持搜索、来源/状态筛选、新建、导入、文件夹、编辑版本、历史恢复、归档及定稿发布，生成队列作为独立卡片放在文档库下方；外部文章和已发布内容的引用监测只放在“效果追踪”，先展示指标摘要，再展示全宽追踪目录，新增追踪从目录工具栏打开宽版 `Modal`。AI 生成的文章标签支持选择腾讯用户/系统标签，也支持直接输入平台内容标签并回车新增，后者随生成结果保存在文档库并作为后续选项复用；效果追踪只显示腾讯真实标签，上游没有标签时明确说明可以跳过。回答页的引用域名与引用文章按 `10/14` 分栏；通知中心先展示通知与规则摘要，在超宽屏把站内通知与规则目录按 `10/14` 分栏，在常规宽度顺序堆叠，新增规则从规则目录工具栏打开 `Modal`；租户积分用量先展示本地账本摘要，再把范围筛选与消费记录连续呈现；平台腾讯计量先展示订阅、积分与周期摘要，再展示范围筛选和记录，扩容操作区在后；后台客户与代理管理把客户等级规则放在账户概览与用户目录之间，便于先维护规则再分配等级。租户发布业务拆成“媒体渠道 / 提交发布 / 发布订单”三个独立路由：提交页采用“左侧发布内容、右侧发布配置”的双栏结构，已从渠道库进入时直接展示所选渠道摘要、费用与余额，通过“更换”再展开搜索选择，避免把渠道下拉框突兀地混入内容字段；渠道库提供行业领域、综合门户、地区、入口、收录、链接、发稿速度、特殊行业、高级选项、价格等全页筛选和分页，不在表单中打开大型渠道弹窗；从渠道库选择后携带草稿上下文回到提交页；订单页只承担履约状态、结果、取消和申诉。旧 `/dashboard/billing` 仅保留兼容跳转。平台管理的发布接入、渠道和订单仍保持独立控制面。登录、初始化等非业务工作区保留适合阅读的局部宽度，不强制铺满屏幕。

## 已迁移页面

租户端全局外壳、分析洞察、品牌监控、内容生成、回答与引用、积分用量、余额与发布、通知中心、腾讯连接、成员权限，以及平台管理端均使用 Ant Design 组件。旧 `tech-theme.css`、`product-theme.css`、`enterprise-theme.css`、`settings-theme.css` 已删除，`@ant-design/pro-components` 已移除；页面布局不再依赖 ProLayout 或旧控件样式。

## 响应式与可访问性

桌面断点以 1200/992/768px 为主。小于 768px 时隐藏非必要用户名和按钮文字，保留图标及可访问名称；业务网格降为两列或一列，禁止页面级横向滚动。触摸目标至少 40px。

移动端使用顶部工具栏与抽屉承载同一组业务导航，不重复渲染桌面侧栏。明暗主题选择写入浏览器存储；首屏恢复完成前不得用默认主题覆盖用户偏好。

所有输入有可见 label，并通过 `htmlFor` 与控件 `id` 建立程序化关联；没有适合显示标签的紧凑行内控件使用仅供辅助技术读取的 label，不把 `aria-label` 挂到无语义的组件外层。图标按钮有 `aria-label`，流程导航有 `aria-current`，键盘焦点使用 3px 可见轮廓。列表条目标题使用普通强调文本，只有进入页面标题层级时才使用标题元素，禁止跳过 H1/H2 形成错误的标题顺序。成功、错误、选中态和危险操作的前景、背景及交互态必须在明暗主题分别校验，不能假定 Ant Design 默认语义色自动满足小字号文本对比度。弹层应能通过 Escape 关闭并管理焦点；动画遵守 `prefers-reduced-motion`。

## 错误与质量门禁

前端交付必须通过：

1. `pnpm --filter @geo/web lint`、测试、类型检查和生产构建；
2. 390px、768px、1440px 三类视口无横向溢出；
3. 登录、分析、生成、发布和平台管理页面无 React hydration、非法 DOM、console error 或失败静态资源；
4. 所有可见业务文本不低于 12px；
5. 请求错误保留可重试入口，超时或响应中断不造成重复提交。
6. 工作台核心页面、系统设置和平台管理在明暗主题下通过自动化无障碍扫描，不得存在可确认的 WCAG 违规项；组件库仅在浮层打开时生成的动态 ARIA 目标作为单独的不确定项跟踪，不可用它掩盖已确认问题。
