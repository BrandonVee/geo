## 腾讯接入、企业与品牌

平台管理员维护唯一固定 Tencent TeamID 和统一 AnswerBit API Key。腾讯接入是系统业务启用的前置条件：首次保存或 Key 轮换使用 `/geo/query/brand` 验证配置并在同一流程导入已有品牌；接入成功前不开放企业、用户、计费或租户业务。配置流程不占用企业业务积分。系统直接使用已接入 OpenAPI，腾讯侧授权由官方控制台管理。

平台企业只来源于腾讯品牌目录。每个 Tencent BrandID 同步为一个内部企业租户投影，承载成员、RBAC、双余额和业务数据；其名称跟随腾讯目录，不存在独立的本地企业创建流程。品牌映射、成员权限、计费和业务数据全部按企业隔离。每家企业仍有一条复用固定 TeamID 的内部兼容记录，但它不是业务层级，也不在页面或管理 API 中展示。企业管理员只看到本企业 BrandID，不能读取其他企业品牌。

任何品牌请求必须明确企业和 BrandID；服务端根据企业自动解析内部腾讯范围绑定，并依次验证统一凭证有效、绑定使用固定 TeamID、BrandID 属于企业。内部绑定异常和品牌范围不符使用不同错误码；上游权限不足使用腾讯返回的授权错误。固定 TeamID 首次配置后不可变更；企业端不能管理内部绑定，也不能自行创建腾讯品牌。

### 工作台企业与品牌范围

工作台保存当前企业以及每家企业各自的品牌选择。切换企业时，客户端必须在同一次状态更新中清空旧 BrandID 和旧业务数据，等待新企业品牌目录返回后再发起业务请求；已过期的目录或分析响应不得回写当前页面。因此请求不得组合新企业和上一家企业的 BrandID。有权访问的URL范围优先于浏览器记忆，用户切换后立即更新地址栏，侧栏与通知入口明确携带当前企业和品牌；浏览器不能保存选择时，刷新与页面跳转仍以URL恢复范围。仅改变页面阶段、其他查询参数或浏览器前进/后退到同企业品牌时，不重新加载品牌目录。品牌选择旁提供只读刷新入口，不调用腾讯同步或写入；权限已变更时可重新读取当前可访问品牌。品牌重试保留同范围最近成功目录和仍被授权的选择，不清空当前工作区输入；目录成功返回后若原品牌不再可用，才清空或切换到可访问范围；明确401/403拒绝授权时立即隐藏缓存目录与旧范围，关闭读取时不保留虚假的加载状态。切换到其他企业或品牌时移除旧问题预选与发布追踪来源，保持页面阶段和其他查询条件；未知范围不得写入浏览器记忆，迟到目录仍按原企业隔离。

### 腾讯资源写入与企业同步

腾讯业务资源实行“上游先写、本地后缓存”：品牌、竞品、问题分类、监控问题和文章的查询、创建、修改、移动或删除都先调用对应腾讯 OpenAPI。只有腾讯返回成功和真实资源 ID 后才更新本地 mapping/cache 与审计，不使用本地伪造成功或离线替代。企业、用户、角色、余额和发布履约是平台自有资源，仍在本地管理。

接入完成后，平台管理员新增企业时，普通创建调用 `/geo/brand/create`；同时填写初始化问题或竞品时，以固定 TeamID 调用 `/geo/brand/bundle/create`。系统把腾讯返回的 BrandID 写入目录，再自动创建对应的内部企业投影；基础资料、Logo 和删除分别调用 `/geo/brand/update`、`/geo/brand/update/icon` 与 `/geo/brand/delete`。只有上游成功才更新或关闭本地投影。删除保留 `closed` 投影、BrandID 映射和历史业务关系，正常列表与授权路径隐藏该企业，后续 Key 轮换验证不得重新激活。

旧的每 TeamID 多 Key、团队级或品牌级 assignment 只保留迁移兼容。统一配置存在时，Web Gateway 与 Worker 使用全局密文，但仍以企业占位 connectionId 记录正常业务调用。

## 监测与分析

工作台覆盖以下能力：

- 总览指标、平台分布、提及率与得分趋势、品牌/竞品排行；
- 监测问题分类、单条和批量问题、启停、改写、移动与删除；
- 大模型回答列表、任务详情、评分、原文和引用证据；
- 引用域名排行、引用文章排行与文章追踪详情；
- 竞品、标题、Prompt 和文章的本地映射。

AnswerBit 是 GEO 指标和内容数据的上游事实源；本地映射承担租户归属、关联、权限与任务状态；选定的只读分析结果另外按请求范围保存有期限的数据库快照。缓存未命中或过期时重新读取腾讯，腾讯明确限流时仅使用同范围、同凭证且不超过 7 天的旧快照；任务状态和写操作仍以腾讯实时结果为准。

<a id="monitoring_workflow"></a>

### 监测问题库操作

启用状态的监测问题由腾讯 AnswerBit 在上游持续执行，Web 的“持续检测”控制台只在首次进入、范围/筛选/分页变化或用户点击刷新时请求任务状态和最新指标，不进行浏览器定时轮询，也不展示最近同步、下次同步、自动同步开关或刷新频率。问题、分类与模型目录独立读取和重试；同一查询刷新失败时保留上一次成功数据，新的筛选/分页查询失败时隐藏旧结果，未成功读取的数量显示“—”。状态明确切换为“请求异常”，展示连续失败次数、归一化错误和立即重试入口；后续请求成功后清除失败状态。品牌目录加载失败提供独立重试，不通过重复选择同一企业伪造状态变化。问题目录以全宽表格直接展示，不依赖展开分类；分类作为筛选与表格字段，新增及编辑使用对应目录触发的弹层。问题目录按上游分页读取，支持模型、关键词、分类和监测日期组合筛选；模型目录来自固定 TeamID 的 AnswerBit 可筛选平台接口，问题行始终展示该 TeamID 的完整监测模型，不随筛选条件缩减，前端统一显示中文名称与图标，请求仍使用上游平台标识。有删除权限的管理员可跨页选择最多 100 个问题并调用腾讯批量删除接口，确认成功后再移除本地映射。企业或品牌切换会清空旧范围数据、筛选和已选问题，取消未完成读取并关闭旧资源编辑态，过期响应不得覆盖新范围；工作区按企业、内部绑定与品牌重新挂载，迟到写入只清理原范围记录，不关闭或清空新范围表单。写操作使用同步提交锁，提交期间锁定弹窗输入与关闭操作；明确失败在原弹窗显示错误并保留输入。新增与编辑的四个问题/分类窗口随当前品牌权限、GEO模块能力和企业服务状态禁用提交；输入保留为可复制的只读内容，窗口内说明原因并提供只读“重新检查权限”，权限或服务恢复后无需关闭窗口重新填写。服务不可用期间检查只刷新企业授权与有效期，不读取被禁止的品牌业务目录；每次目录写入还在暂存操作之前检查当前所需的创建、更新或删除权限，未完成及待核对请求不因权限变化自动重发。新增分类与问题使用共享接口契约在本地校验：名称最多255字、描述和单个问题最多2000字；批量问题逐行去掉空白和空行、合并完全相同的重复内容，实时显示实际数量，每次最多100个不同的问题。

腾讯目录写入没有可重放的上游幂等契约。请求发送前在当前浏览器标签页按用户、企业、内部绑定与品牌暂存操作类型、原内容和新增表单；网络中断、5xx或无法解析的响应视为结果待核对，阻止新的目录写入但保留查询、筛选与分页。刷新或切换回来后恢复原记录，不自动重发。同一页面切换回来时，如果原请求仍在执行，核对按钮继续锁定；原请求结束后通知当前工作区，明确成功会清理原记录并刷新当前目录。用户从“刷新目录核对”关闭原弹窗、实时读取分类与当前页问题，再按原内容搜索或翻页核对；读取成功后才能明确“已核对，结束本次操作”。该动作只清除本次待核对记录，不宣称上游写入成功，也不再次提交；新增输入保留，编辑则从当前目录重新打开。收到明确成功或4xx拒绝才自动结束暂存，列表刷新失败不回退已经完成的写入。存储不可用提示保持页面打开；已有记录无法读取时阻止写入，不静默丢弃。

### 竞品目录与分析衔接

总览页与其他工作区复用同一企业/品牌范围读取与恢复逻辑，优先恢复URL中有权访问的企业与品牌，没有指定时使用本用户可用的上次选择；切换后更新URL，刷新、浏览器前进/后退和增长行动跳转保持范围。等待新企业目录时品牌栏与操作区隐藏旧品牌，不保留上一企业的品牌标签；只读品牌刷新与失败重试保留同范围竞品输入，并即时更新角色。品牌、模型与竞品目录独立读取和重试，模型不可用不阻止选择已授权品牌，竞品不可用不阻止查询品牌自身指标。竞品目录与新增、编辑和删除按企业、内部绑定及品牌重新挂载；迟到写入只更新原范围暂存，不关闭新范围弹窗。目录支持名称/别名搜索、排序及5/10/20条分页，写入后刷新目录，保留当前检索和分页；删除末页记录时由表格回退到有效页。目录读取失败单独显示重试，不能显示为“还没有添加竞品”。查看者只能读取，创建、编辑与删除入口分别按角色及GEO模块权限开放。

新增与编辑在提交前使用共享接口契约校验去掉首尾空白后的名称和别名，名称1–255字、别名最多255字。正常保存一步完成；提交期间使用同步写入锁，锁定输入与弹窗关闭。明确拒绝在原弹窗或删除确认层展示错误并保留输入，不因分析查询失败清空已经完成的写入。未提交的同一编辑关闭后可继续输入；切换编辑对象从该竞品当前目录值开始。权限刷新后若新增、编辑或删除能力已被撤销，已打开窗口显示对应权限说明并禁止提交；编辑输入保留为可复制的只读内容，关闭后仍保留草稿，恢复权限后可重新打开继续保存。未完成的写入或待核对记录仍按原请求处理，权限变化不自动重发或清除记录。

腾讯竞品写入没有可重放的幂等契约。发送请求前在当前浏览器标签页按用户、企业、内部绑定与品牌暂存操作类型、原名称/别名及资源ID；网络中断、5xx或无法解析的响应保留原记录，禁止新写入但允许目录检索，刷新后恢复，不自动重发。切换回原企业时，如果原请求仍在执行，核对继续锁定。用户从“核对竞品目录”实时读取完整无筛选目录；已知ID的编辑只有名称与别名均匹配才确认完成，删除只有目录中该ID确实不存在才确认完成。无ID的新增不能仅因同名记录存在便宣称原创建成功，需要用户按原内容核对后明确结束本次操作，该动作不发起写入；原新增和编辑输入继续保留。存储不可用时提示保持页面打开，无法读取已有记录时不静默丢弃。

竞品目录更新后，分析查询使用当前完整竞品ID集合，每次最多100个，超过时分批查询并合并趋势与排行，品牌自身统计只保留一份，排行按ID去重；不截断目录以绕过查询限制。核心指标、曝光趋势/排行与得分趋势/排行的查询结果分别呈现，失败组提供持久错误及重试入口，不阻断其他成功结果。范围、日期、模型或竞品集合变化立即隐藏旧分析结果，迟到结果不能覆盖当前条件。增长行动中的问题、回答证据和内容生成链接明确携带当前企业与品牌，避免返回时丢失上下文。

<a id="answer_evidence_workflow"></a>

### 回答与引用证据查询

回答、引用域名、引用文章和模型目录独立读取并提供各自重试，单项迟迟未返回或失败不阻断其他已完成结果。同一条件主动刷新失败时保留该条件上次成功的数据；日期、模型、关键词或页码变化后隐藏旧结果，未成功读取的数量显示“—”，失败不能表示为“暂无记录”。默认按浏览器当地日期选择近7天。回答使用每页20条，域名与文章分别每页10条，以各接口返回的真实总数独立分页；回答翻页不改动引用分页，不截取引用文章前8条；读取发现总数缩减时回退到该目录有效末页。日期、模型和关键词变化重置三个页码，品牌提及仅作用于回答并重置回答页码；关键词回车立即使用当前输入条件。

点击查看回答立即打开详情抽屉，展示读取状态，原回答详情不作为下一条的加载占位。详情失败在原抽屉显示可重试错误；关闭、切换记录或企业/品牌时取消旧读取，迟到结果不能重开已关闭抽屉或替换新记录。引用表格在窄屏仅于表格内滚动，详情按视口减少每行字段。

## 分析—生成—发布闭环

租户工作台以企业和品牌为统一范围，提供三段式业务导航；内部腾讯范围由企业自动确定：

1. **分析**：`/dashboard` 汇总提及率、平均排名、得分、趋势和竞品；问题监测与回答证据用于定位内容机会；
2. **生成**：`/dashboard/content?stage=generate` 读取模板、目标问题和标签，调用 `/v1/answerbit/article-jobs` 创建异步文章任务；
3. **发布**：生成任务详情在用户完成审核后，可将内容标题和来源任务预填到 `/dashboard/publication/new`；用户可在提交页快速搜索选择渠道，也可在 `/dashboard/publication/channels` 按行业、门户、地区、入口、收录、链接、速度、特殊行业、高级属性和价格全页筛选，选择后携带渠道与草稿上下文回到提交页，通过 `/v1/publication-orders` 创建人民币计费发布单，再到 `/dashboard/publication/orders` 跟踪履约状态和结果链接。提交页只读取当前品牌发布余额，不承担企业到品牌的资产划拨；拥有 `balance.allocate` 的企业管理员在独立 `/dashboard/balances` 页面管理企业资金池、品牌账户和划拨流水。聚合发布由 Worker 每 5 分钟同步，无需打开页面；订单页可见且在线时每分钟刷新，切换企业或品牌重新挂载工作区并清空旧数据与弹窗，读取请求取消和版本检查防止旧结果覆盖。相同投稿表单重试复用幂等键，结果不确定时保留稿件；来源文章可主动切换为手工正文。

已发布订单可直接进入[效果追踪](#article_tracking)，复用标题与公开结果链接。每一阶段都复用同一品牌范围。上一步输出由用户审核后进入下一步，平台不自动把生成内容直接发布；生成失败返还腾讯积分，发布失败或取消返还发布人民币余额。

<a id="publication_drafts"></a>

### 投稿草稿与跨页衔接

文档发布、渠道选择及订单跳转显式携带企业和品牌范围，客户端只接受当前用户有权访问的范围。投稿内容在当前浏览器标签页按用户、企业与品牌保存草稿，24 小时后失效；进入渠道库或刷新后恢复标题、正文、来源、要求与渠道，明确提交成功后清除。网络失败与上游结果不确定时保留稿件及原幂等键，避免重试重复投稿。更换企业或品牌只读取目标范围的草稿；明确选择新的来源文章时使用新的文章。

手工投稿默认输入普通正文，提交时把段落转换为 HTML 并转义文本；熟悉 HTML 的用户可主动切换格式。从文档或生成任务读取的正文，已有 HTML 保留格式，普通文本在服务端转为 HTML。渠道报价和余额刷新不覆盖用户已选择的渠道，正式提交仍由服务端重新计价和验证余额。

<a id="publication_orders"></a>

### 发布订单查询与履约操作

租户订单页按当前企业与品牌在服务端分页，默认每页 20 条，可选择 10、20、50 或 100 条。支持文章标题、媒体名称或订单编号的文字搜索，以及状态和提交日期筛选；文字中的百分号和下划线按普通字符匹配。提交日期使用北京时间的完整日期边界，开始与结束日期必须同时提供且顺序有效。记录按提交时间和订单 ID 倒序稳定排序，总数与本页来自同一只读快照，超出末页时返回实际末页，空列表返回第 1 页。

页面将已应用条件与页码保存在 URL，刷新及从追踪返回时恢复。更换企业或品牌时在更新范围URL的同时清空旧订单条件与页码，再挂载新工作区；条件改变后立即隐藏旧列表，取消旧读取，迟到响应不得覆盖新结果。状态、日期或关键词变化回到第 1 页，清除筛选不会丢失当前品牌。查询失败提供重试，余额读取与订单读取独立，单项失败不阻断另一项。取消或申诉成功后刷新当前条件和品牌余额，最后一页记录移出筛选范围时回到实际末页。

取消与申诉在发送前检查当前发布权限并共享提交锁，防止重复操作。申诉提交期间锁定输入与关闭操作，失败在原窗口保留说明；权限或企业服务状态变化后，窗口禁止提交并允许只读重新检查，恢复后继续原输入。提交发布页也保留未提交的稿件，具体权限、计费和履约约束见[发布订单状态机](./balance_and_publication.md#publication_state_machine)。

取消与申诉发送前按用户、企业、内部绑定与品牌暂存原订单、操作类型及申诉原因/说明；存储不可用时不发送写入。网络中断、无法解析的响应或服务端异常保留待核对记录，刷新和切换回来后不自动重发，并阻止新的订单取消/申诉。返回仍在执行的原范围时继续锁定，明确成功或拒绝只清理原范围记录，完成后刷新当前原范围目录。核对通过原订单完整编号查询，不受当前搜索、状态、日期或页码限制；查到已取消、售后中或已终止状态后解除锁定，读取失败或没有找到原订单则保留记录。订单行显示服务端待核对标记和“核对原操作”，其他管理员或新设备也可恢复原操作内容；旧列表尝试写入遇到409时恢复服务端原记录和说明。核对发现当前操作编号已变化时改为显示真实当前操作，已完成、拒绝或结束的记录解除本地锁定。仍无法确定时允许继续核对；成功读取后，具有发布权限的用户核对上游并填写说明，按服务端原编号明确结束本次操作。执行中且未超过期限不能结束；查看者只允许读取核对。保存说明响应丢失后保留记录，通过再次读取订单确认结束，不重复保存。只有没有服务端操作记录的历史本地记录才仅清理浏览器记录；两种结束方式都不宣称原操作成功、不重发、不退款。

即时上游同步只处理本次授权分页中的订单，完成后重新读取筛选结果；其他订单继续由 Worker 的周期维护同步，不会为每次翻页把企业历史全部加载到应用内存或返回浏览器。查看历史不投稿、不扣费，状态变化和返还仍由原履约状态机处理。接口响应继续以 `data` 返回订单数组，另在 envelope 的 `pagination` 返回实际页码、每页数量、总数和总页数。

## 内容与异步文章

监控问题可携带明确企业、品牌与问题范围跳转到生成页并预选目标问题。文档库、生成和效果追踪各自读取所需数据；效果追踪不可用时不阻止生成或读取本地文档。切换企业或品牌清空旧范围的目录与详情，并恢复目标范围的生成草稿，迟到的生成提交与查询结果不得覆盖新范围。

生成草稿在当前浏览器标签页按用户、企业、内部绑定和品牌暂存，普通与参考两种方式分别保留模板、语言、目标问题、标签、补充资料及参考链接。未提交草稿 24 小时后失效；待确认提交保留完整原请求、报价及幂等键，不因超时自动遗忘。刷新、离开页面或切换范围再回来均恢复对应草稿；存储不可用时提示保持页面打开，未清空的输入或待确认请求触发浏览器离开提醒。已选模板从目录移除时要求重新选择，不自动替换为另一个模板。

结果不确定时，“确认上次提交”发送原请求与原键，允许用户继续编辑，但后续输入不会改变原提交。确认成功只清除与已提交内容一致的表单；后续修改和另一生成方式的草稿保留，用户明确再次提交才创建新任务。明确的输入、模板或报价错误允许修正后用原键重试；若修正请求返回幂等冲突，页面用该键确认之前保存的原请求，保留修正后的输入。待确认期间不能清空草稿；普通草稿可通过确认清空。

生成提交在网络失败时复用同一幂等键；服务端只允许原操作者在原企业、品牌、内部绑定及相同内容下重放，输入或操作者不一致时返回 `ARTICLE_JOB_IDEMPOTENCY_CONFLICT`。任务、pg-boss 入队、队列编号和提交审计在同一事务中写入，提交完成前 Worker 看不到任务；入队或审计失败全部回滚，原键可以重试。相同企业和提交键的并发请求在事务锁内复核原请求，只创建一个任务。旧的等待任务尚无队列编号、执行租约和腾讯 ArticleID 时，可用原键补全入队，保留原加密请求和积分价格快照，不重新读取模板或计价。正在执行或已结束的任务只返回原状态，不重新投递。等待中的任务可以取消；确认生成任务失败或取消后重新提交会使用新的键。

生成工作区分为“普通文章生成”和“参考文章生成”：普通入口只显示 `is_high_ref=0` 模板；参考入口只显示 `is_high_ref=1` 模板并要求参考文章链接。首次进入另一方式沿用公共输入，重新选择模板且不沿用参考链接；之后切换恢复各自草稿，普通提交不携带隐藏参考字段。没有匹配模板时禁用新提交，仍可确认已保存的原请求。服务端按所选语言校验模板目录，拒绝不可用模板、缺少参考资料的高引用模板以及携带参考资料的普通模板，通过后才创建任务。

任务响应的 `generationMode` 为 `standard`、`reference` 或 `null`，由已保存的加密请求解析，不依赖当前模板目录判断历史任务。无法解析的旧请求标为方式未知，不阻断列表；响应不暴露请求密文或参考正文。生成页各入口显示对应方式的最近任务，完整任务记录保留两类及未知历史任务，结果统一入本地文档库。

用户可读取文章模板、追踪公开文章，并提交文章生成任务。Web 完成输入、权限和品牌范围校验后，将稳定标识写入 `article_generation_jobs` 与 pg-boss。AI 文章生成不限制任务次数，仅按功能积分结算。

管理员通过 `/admin?section=library` 按企业维护全平台正常启用企业的文章；代理商与普通用户在工作台查看已获授权企业／品牌的全部文章。文章列表分页读取，切换企业／品牌清空详情和编辑弹窗，防止旧范围内容残留。具体权限边界见[身份与访问控制](./identity_and_access.md)。

平台文档库由 `content_documents`、`content_document_versions` 与 `content_folders` 组成，并按企业、内部团队绑定和品牌隔离。用户可以新建草稿、粘贴导入带来源链接的外部文章、设置本地标签和文件夹；每次修改都会递增版本号，并保存标题、正文、状态、语言和标签的不可变版本快照，恢复历史内容也会生成一个新的最新版本，不覆盖原历史。删除文件夹只把文档移至未归档，归档文档使用 `archived` 状态保留正文和版本。

新建、导入和冲突另存的界面在首次提交前暂存创建标识及原始内容；网络错误或成功响应丢失后，包括刷新或切换范围再恢复，使用同一 `Idempotency-Key` 确认原请求，最多创建一份文档与首版。同一企业下原操作者、内部绑定、品牌或创建内容不一致返回 `409 CONTENT_DOCUMENT_IDEMPOTENCY_CONFLICT`。服务端保存初次请求的指纹，后续修改、恢复或归档不会影响创建重放，重放返回文档当前状态。用户在结果未确认时继续输入，重试先找回已保存文档，再把后续输入保留为该文档的待保存编辑；已出现他人新版本时继续走冲突核对。明确的输入或文件夹错误允许修正后重新提交；文档、首版与创建审计在同一事务写入，审计失败一并回滚；重放不重复记录创建审计。

文档修改、历史恢复和归档必须提交打开内容时看到的 `expectedVersion`。Repository 在同一事务锁内比较当前版本，过期编辑返回 `409 CONTENT_DOCUMENT_VERSION_CONFLICT`，不改变正文或历史；恢复与归档冲突后页面刷新详情，用户需重新确认操作。编辑冲突保留用户表单，独立读取最新版供核对和复制；用户可手动合并后明确确认保存，服务端仍按刚核对的版本校验，也可另存为新文档或确认载入最新版。

未保存编辑在当前浏览器标签页按用户、企业、内部绑定、品牌及文档暂存 24 小时，新建手工稿和导入稿各自保存。切换范围、离开文档标签页或刷新后，可通过“继续编辑”恢复；恢复已有文档先检查当前读取权限并获取最新版，若版本变化直接进入冲突核对流程。暂存不写入服务器，也不能用于发布。明确保存成功或放弃编辑后清除对应暂存，存储不可用时提示用户保持页面打开；未保存编辑仍打开时刷新或关闭页面会触发浏览器离开提醒。

AI 生成成功时，Worker 在完成生成任务和上游文章映射的同一数据库事务中，以 `source_job_id` 幂等创建状态为 `ready` 的本地文档及首个版本；迁移会把升级前已成功的生成任务补入文档库。生成任务仍保留用于队列状态、计费、恢复和审计，文档库负责后续编辑、分组和发布。文档定稿后可把 `sourceDocumentId` 交给发布单，服务端重新验证品牌范围、`ready` 状态和非空正文，再把数据库中的正文提交给所选渠道。

腾讯文章创建先返回 ArticleID，正文通常在 5–10 分钟后可用。Worker 将 ArticleID 持久化后每 30 秒重新投递结果查询；调度在行锁内核对当前执行租约和 ArticleID，结果查询入队、队列编号更新和执行租约释放一起提交，失败时保留原状态，迟到的旧执行不能再安排查询。上游状态为 `0` 或正文为空时任务保持 `running`，不写入空文档。超过 20 分钟仍无正文时以 `ARTICLE_GENERATION_TIMEOUT` 结束并返还功能积分。生成页可离开等待；页面可见且在线时每 15 秒只刷新任务状态。发布提交页可搜索当前品牌已定稿的腾讯 AI、手工或导入文档，使用所选文档的最新正文。

Worker 执行时重新加载任务、内部腾讯范围与品牌授权，并在计费和外部调用前解密、校验任务请求载荷。载荷必须通过共享的 AnswerBit operation Schema，且 BrandID、模板与语言必须和任务的不可变字段一致；密文损坏、旧数据结构异常或范围不一致时以 `INVALID_ARTICLE_JOB_PAYLOAD` 终止，不产生积分扣减，也不向腾讯发送请求。Web 在创建新任务时校验用户看到的积分报价，并把等级、基础积分、加价率和最终积分保存为任务价格快照；Worker 校验载荷后按快照预扣一次，再免费调用所需 AnswerBit operation。升级前未保存快照的等待任务仍按执行时的规则计价。任务状态为 `queued`、`running`、`succeeded`、`failed` 或 `cancelled`；完整功能失败时按原扣款金额返还积分；等待中的任务取消时尚未开始计费。

Worker 每 5 分钟对账文章和报告任务：`queued` 超过 10 分钟、`running` 超过 15 分钟才进入恢复候选；pg-boss 中仍为等待、重试或执行状态的任务保持不变。安全候选会清除旧执行租约并重新投递；文章自动补投在行锁内复核候选队列编号，入队和队列编号回填原子完成，其他请求已恢复的候选不重复投递。文章已经保存腾讯 ArticleID 时只恢复内容读取，不重复创建文章。已经扣除功能积分但没有 ArticleID 的中断文章存在上游结果不确定性，因此终止为 `ARTICLE_RECOVERY_UNCERTAIN` 并幂等返还原扣款，不再次调用创建接口。每次 Worker 领取任务都会写入新的 `execution_id`，后续中间态和终态更新必须匹配该值，旧执行即使迟到也不能覆盖恢复后的新执行。

## 公开文章效果追踪

已发布订单可从“加入效果追踪”进入同企业、同品牌的追踪表单。页面只携带订单 ID，不把标题与链接作为可信查询参数；服务端同时校验发布读取与内容创建权限、订单归属、已发布状态及 HTTP(S) 结果链接，读取不调用腾讯、不扣积分。空表单自动带入标题和发布链接；已有普通草稿先由用户选择保留或确认替换，待确认提交不能被发布来源覆盖。用户检查语言及标签后明确点击加入，复用正常追踪的报价与幂等流程；订单未发布、已退稿或来源读取失败时显示原因并允许重试。

追踪录入使用独立的语言、标题和公开链接表单，不与生成草稿共享语言或输入。公开链接只接受 http/https，每次最多 20 个，页面去除重复链接。草稿按用户、企业、内部绑定和品牌在当前标签页暂存；普通草稿 24 小时失效，待确认提交保留原输入与键。切换范围取消旧提交和详情读取，迟到结果以及之前选择的文章详情不得覆盖当前工作区。服务端读取追踪详情前校验 ArticleID 已在当前企业、内部绑定与品牌的目录映射中，未知或其他范围文章返回 `ARTICLE_NOT_FOUND`，需要先刷新当前范围目录。用户按当前企业和品牌创建一次提交，服务端保存原操作者、范围、加密请求及稳定幂等键，重复请求只能确认原提交，不重复调用腾讯或扣积分。

本地提交、积分预扣和创建审计在同一事务中完成，再调用腾讯。腾讯明确成功后先保存真实 ArticleID，随后原子完成文章映射与成功审计；后续本地写入失败可以用原键或由 Worker 后台恢复，不再次创建追踪。明确拒绝会标记失败并返还原积分。网络超时、5xx 或成功结果无法解析时保留结果不确定状态，同样返还积分，但不自动重新创建；用户先查询追踪目录核对；页面显示最近的个人提交及原链接，确认按钮只查询原提交。用户明确“已核对，结束本次确认”后保留输入，下一次主动加入追踪才使用新键；普通失败可直接修正输入重新提交。已中断超过一分钟且没有 ArticleID 的提交按结果不确定处理，迟到的真实结果仍可完成原提交，不再次扣款。

## 保存视图与报告

回答、引用域名和引用文章页面可保存个人筛选视图。视图归当前用户和企业所有，保存企业、内部绑定、品牌、日期、平台、关键词和品牌提及条件，并支持恢复、重命名和删除。回答视图按 GEO 模块授权；保存时即使旧客户端只给 BrandID，也会解析内部绑定并校验品牌归属和当前用户权限。损坏筛选或已经变更的品牌范围不会应用到当前页面。切换企业或品牌清空旧列表、筛选与详情，取消旧读取；迟到响应与操作结果不能影响新工作区。同一企业下切换页面阶段、重新读取企业目录时保留当前品牌，不能因目录对象更新把工作区重置为空。品牌目录就绪前筛选控件保持禁用，避免输入被加载过程清空；回答和两类引用读取独立处理，单项失败保留其上次数据并显示错误，不阻止其他成功数据展示。

拥有 `report.export` 的企业管理员或品牌管理员可创建 CSV 导出。报告使用当前日期、平台和关键词；回答导出还保留品牌提及筛选，关键词对应上游问题筛选。提交按企业范围保存幂等键，只允许原操作者以相同品牌、绑定、报告类型和筛选条件重放，不一致返回 `REPORT_EXPORT_IDEMPOTENCY_CONFLICT`。报告记录、额度预留、pg-boss 入队和创建审计使用同一 PostgreSQL 事务；事务提交前 Worker 看不到任务，入队或审计失败全部回滚，额度不足不创建半成品。相同“企业 + 提交键”的并发请求在事务锁内校验并返回同一任务。网络失败后在当前标签页保存待确认提交键，刷新并恢复相同筛选后继续使用原键；确认收到任务后清除。Worker 再次验证企业成员和品牌权限，并重新校验数据库中的筛选条件；异常筛选以 `INVALID_REPORT_EXPORT_FILTERS` 终止，不调用上游。单个文件最多输出 10,000 行和 16 MiB UTF-8 内容，分页累计源数据或最终 CSV 超限时以 `REPORT_EXPORT_TOO_LARGE` 终止，避免 Worker 内存和数据库被异常上游字段无界占用。导出使用平台内部报告额度；文件成功后可下载，并在 24 小时后进入 `expired` 且清理数据库中的文件正文。

报告记录默认每页 5 项，支持调整页容量，并按提交时间与 ID 稳定倒序排列；服务端在同一租户只读快照中读取总数与当前页，超界页码回到末页，空结果回到第一页。可按文件名、报告编号、原关键词、类型、状态和北京时间提交日期组合检索；提交日期与报告内的数据日期分别展示。文件到期的成功任务即时归入 expired 筛选，不依赖 Worker 清理。筛选和页码保存到 URL，刷新可恢复；切换企业或品牌不沿用另一范围的条件。报告元数据查询只返回授权企业、绑定和品牌，不读取或返回 CSV 正文，允许有报告权限的用户查看同品牌的历史任务。页面展示中文状态、原筛选、行数、文件到期时间和可理解的失败原因。等待或运行中的任务只在页面可见且在线时每 5 秒刷新状态，恢复可见或联网后补拉；无待处理任务时每分钟同步历史记录；报告与个人保存视图独立读取、报错和重试，读取失败隐藏不可确认的列表与总数。新提交不覆盖正在检索的历史筛选，通过“查看本次报告”直接定位真实任务。也可主动刷新。失败或过期任务支持按原筛选重新导出，使用新提交键；下载请求继续由服务端复核权限和有效期，失败在当前页面反馈，过期后改为重新导出入口。状态读取即时识别已过期文件，不依赖周期清理时间。

旧版本留下的等待任务若缺少预占或队列关联，相同提交重试会在事务内补全原任务，不重复占用已有预留；无法恢复时原任务明确失败，页面可用新键重新导出。Worker 每次领取前在行锁内复核该任务的稳定预留键、报告引用和原操作者；缺失的真实预占先补齐再进入执行，无额度或已经结算的任务不执行、不抢占其他任务的额度。历史预占的操作人为空时保留历史事实，仍可按报告引用恢复。

报告导出不调用具有创建副作用的上游接口，过期的等待或执行任务可安全回到 `queued` 并重新投递。自动补投在行锁内核对候选队列编号，额度预留、入队和新队列编号一起提交；已被其他请求修复的候选不重复投递，入队失败整体回滚并等待下次对账，无额度或预留已结算时明确失败。恢复后的 Worker 仍会重新验证企业、成员和品牌权限。旧执行同样受 `execution_id` 隔离，不能写入新执行的文件或失败状态。

<a id="notification_workflow"></a>

## 通知

企业通知规则包括：

- `low_credits`：本企业品牌的平台 AnswerBit 积分不足；
- `connection_failure`：AnswerBit 连接异常；
- `metric_anomaly`：曝光、得分或平均排名指标异常。

Worker 每 15 分钟评估全部已启用规则，保证没有用户访问工作台时仍持续检测；成功读取总览指标时也会即时评估对应品牌的指标异常规则。通知写入在规则级事务锁内按冷却窗口去重，多个 Web/Worker 实例并发评估不会重复发布。连接失败规则只读取最近 24 小时真实业务调用日志与本地连接状态，不再主动请求腾讯品牌目录；达到配置次数时产生 warning，连续失败达到 `max(配置次数 × 2, 5)` 时升级为 critical；评估器读取足够覆盖 critical 边界的最近调用记录，并在最新成功调用处重置连续失败计数。提及率和 GEO 得分下降触发指标异常，平均排名数值上升触发指标异常，波动达到阈值两倍时升级为 critical。

通知页每分钟自动同步通知和规则健康状态，页面隐藏或离线时不发起轮询，恢复可见或联网后立即补拉；企业切换会先清空旧企业数据，过期响应和旧范围写操作结果不得覆盖新企业。企业管理员可查看启用规则数、最近评估错误数、每条规则的最近评估时间和错误码；规则单次评估失败后保持启用，由 Worker 下一周期继续重试。通知属于企业，`notification_reads` 保存每个用户独立的已读状态。企业管理员可管理规则；具有 `notification.read` 且处于有效数据范围的用户读取通知。

通知历史使用服务端分页，按触发时间与 ID 倒序稳定排列；类型、严重程度、只看未读和北京时间日期取交集，超界页码回退到末页。筛选与页码可经 URL 恢复，切换企业不沿用另一企业的通知条件。未读摘要始终为当前用户在授权企业范围的全部未读数。企业管理员可见企业全部通知；其他角色需要品牌授权，不能仅凭企业成员角色读取企业级通知。逐条已读/未读以及“当前筛选全部标为已读”只影响本人，批量操作覆盖全部匹配页且可安全重试。通知和规则独立读取、独立报错与重试，读取失败显示未知摘要，不伪装成零。

规则创建按企业、类型和范围串行去重；相同操作者及完整配置重放返回原规则，不重复审计，不同配置或操作者返回冲突。更新必须携带 `expected` 原配置，行锁内比较配置字段，其他管理员改变配置时返回最新配置并保留当前输入；Worker 更新评估时间或错误状态不会产生配置冲突。规则变化和审计同事务提交，审计失败整体回滚。保存失败保留弹窗和值；响应丢失或 5xx 时先只读核对完整配置，未核实则保留原命令，允许再次核对或原内容重试。待核实命令按用户、企业暂存在会话存储，刷新恢复后先核对结果；常规创建、阈值保存与启停仍为单步操作。

<a id="quota_reservations"></a>

## 平台资源额度

成员数、品牌数、Prompt、单品牌竞品数、报告导出数和数据保留天数可由平台内部 entitlement 管理，但不组成对外品牌套餐。AI 文章生成和效果追踪不使用次数额度，改由品牌积分按完整功能结算；预留重放会核对权益、数量、业务引用和已记录的操作用户；已经结算的预留不能再次作为有效预占。需要周期额度的异步资源继续通过 reserve/commit/release 流水保证失败时释放占用。同一次预留的确认和释放通过共同事务锁互斥，只能结算一次；重复同操作返回原流水，相反操作返回 `RESERVATION_ALREADY_SETTLED`，不能从其他任务的预占总额中重复扣除。
