# 身份与访问控制

本文定义账号生命周期、首次初始化、认证、平台/企业 RBAC 与品牌范围，是身份和权限行为的当前权威说明；具体数据库隔离机制见数据与安全架构。

## 账号类型与角色

`users.account_type` 记录账号运营类型：

- `admin`：平台管理员账号，可被授予 `super_admin`；
- `agent`：代理商账号，可作为企业管理员或企业成员参与企业运营；可通过 `agent_valid_from` 与 `agent_expires_at` 设置生效和到期时间，两者为空表示长期有效；
- `customer`：企业客户账号，通过成员关系获得企业或品牌角色。

`users.pricing_tier` 独立表达商业价格等级：普通用户为 `retail`，代理商可选择 `bronze`、`silver` 或 `gold`。客户和管理员固定使用 `retail`；账户从代理商切为客户时同步回到 `retail`，客户切为代理商时默认使用铜牌等级。价格等级不授予任何权限，只决定聚合发布售价与完整业务功能的积分计费系数。

账号类型不直接等于权限。有效权限来自角色：`super_admin`、`tenant_admin`、`brand_admin`、`brand_editor`、`brand_viewer`。`super_admin` 为平台范围；其余角色为企业范围。品牌管理员、编辑者和查看者还受 `brand_access` 限定；平台还可用目标企业功能范围进一步收窄单个用户在单家企业内可使用的模块。

<a id="bootstrap_flow"></a>

## 一次性初始化

全新数据库完成迁移与种子后，`/setup` 是唯一首次管理员入口：

1. 页面调用 `GET /api/v1/system/bootstrap` 判断是否已有本地凭证账号；
2. 用户提交名称、用户名、密码与确认密码；用户名规范化为小写，密码至少 12 位且同时包含字母和数字；
3. `POST /api/v1/system/bootstrap` 在事务中获取 PostgreSQL advisory lock；
4. 系统再次确认 `credential` 账号数为零，创建 `admin` 用户、scrypt 密码哈希和 `super_admin` 授权；
5. 接口返回 `201` 和 `Location: /sign-in`，页面硬跳转到 `/sign-in?initialized=1` 并显示成功提示；
6. 一旦存在本地凭证账号，后续初始化返回 `409 SYSTEM_ALREADY_INITIALIZED`，`/setup` 不再开放创建。

初始化依赖种子中的 `super_admin` 角色；角色未就绪时返回 `503 SYSTEM_NOT_READY`。并发初始化只能有一个请求成功。

初始化页在挂载、窗口重新聚焦和历史页面恢复时，通过不缓存的状态查询复核初始化状态。创建返回 `201` 或 `409 SYSTEM_ALREADY_INITIALIZED` 时进入登录；请求中断或服务端异常时先查询状态，避免已入库却停留在创建页。成功状态隐藏表单并提供“前往登录”链接，作为自动跳转的后备入口。

## 登录与会话

系统仅支持用户名和密码登录，不开放自助注册、短信验证码或手机号登录。Better Auth 使用用户名插件和 credential provider：

- 用户名为 3–32 位，以小写字母开头，只含小写字母、数字和下划线；
- 密码长度为 12–128 位，创建入口额外要求同时含字母和数字；
- 密码只以 scrypt 哈希保存，服务端不保存明文；
- 登录端点按用户名规则每分钟最多 8 次，总体认证限流每分钟 100 次；
- Session 有效期 7 天，每 24 小时允许刷新；生产环境使用安全 Cookie；
- `disabled` 用户禁止登录，管理员停用账号时撤销现有 Session。
- 代理商在生效时间之前或到期时间之后禁止登录，已有 Session 的页面与 API 请求也会重新检查有效期；客户和管理员不使用代理商有效期字段。

## 平台管理权限

`super_admin` 拥有全部权限，可在 `/admin` 管理腾讯接入、企业、平台用户、企业成员关系、企业与 Tencent BrandID 的分配、审计、调用健康、企业余额、积分单价、发布渠道和发布履约。固定 AnswerBit TeamID 与统一 API Key 只属于平台腾讯接入配置，Key 可调用的上游权限由腾讯官方控制台管理。平台操作必须经 `requirePlatformPermission` 验证数据库中的角色—权限关联，不能仅检查 `account_type`。

后续账号统一由平台管理员创建，但必须先完成腾讯统一接入。创建管理员账号会同时授予 `super_admin`；创建代理商或客户账号后，再通过企业成员接口绑定组织和角色。平台企业只由固定 TeamID 的腾讯品牌生成：平台新增调用腾讯创建品牌，首次配置和 Key 轮换会导入已有品牌并补建缺失投影；首次投影时由操作的 `super_admin` 成为初始企业管理员，之后可在企业详情绑定用户、转移管理员、启停成员或配置品牌角色，并始终执行“至少保留一名有效企业管理员”的约束。历史未映射和已关闭企业不进入正常企业目录。

平台管理员可以在客户与代理商之间切换账户类型，并设置代理商为长期有效或指定生效—到期区间。用户编辑窗口同时维护代理价格等级、企业额度、品牌创建额度、腾讯积分划拨额度，以及该用户在每个目标企业的功能授权范围。客户切换为代理商前必须移除全部显式品牌权限；代理商切换为客户前必须转移并移除全部企业管理员角色，避免账户类型与现有权限模型冲突。管理员账户类型不可在此流程中降级。类型切换会撤销现有 Session，价格等级在服务端每次结算时从用户记录重新读取，生效时间和到期时间则在每次访问时即时判断。

平台用户详情聚合其全部企业成员关系和品牌访问范围；平台企业详情聚合企业信息、对应 Tencent BrandID 和成员。内部腾讯范围绑定只用于兼容现有外键，不作为平台管理资源。完整控制面见[平台管理架构](../architecture/platform_administration.md)。

## 企业与品牌权限

`tenant_admin` 拥有除 `platform.*` 外的企业权限，可管理企业设置、成员、企业余额划拨、品牌业务、报告和通知规则。固定 TeamID、统一 API Key 和企业 BrandID 分配由平台管理员维护；企业管理员和代理商只能查看本企业品牌接入与健康状态，不能创建、轮换或删除密钥。腾讯上游授权不属于租户权限模型。企业管理员或代理商可把企业资金池划分到品牌，但只有平台管理员可向企业资金池入账。

品牌访问按“企业有效成员 + 企业角色权限 + 本企业品牌授权”联合判断：

- `brand_admin`：可读写品牌资源、创建发布单和导出报告，但不管理企业连接、成员或余额划拨；
- `brand_editor`：可读写品牌资源和创建发布单，不删除资源或导出报告；
- `brand_viewer`：只读品牌资源、余额、发布单和通知。

未指定品牌的企业级查询走企业权限；指定品牌的查询必须经过 `authorizeBrand`，同时验证企业处于 active、内部 Team 绑定有效且属于企业、品牌映射属于该企业与 Team，以及当前用户的授权关系；企业管理员也不豁免资源归属校验。服务端会自动解析内部腾讯范围绑定，客户端不选择团队。

<a id="feature_scope"></a>

## 目标企业功能范围

`organization_user_feature_scopes` 按 `user_id + organization_id` 保存模块 allowlist。授权顺序为角色/品牌角色先确定能力上限，再与显式功能范围取交集，因此范围只能减权，不能授予角色原本没有的权限。没有范围记录时继承角色默认能力；存在空数组范围时，该用户在目标企业内的全部业务模块均关闭。

当前功能模块为：GEO 数据与腾讯能力、内容与素材、内容发布、余额与积分划拨、报表导出、通知中心、成员与审计、企业设置。功能范围只影响指定企业，在另一家企业可使用不同组合。用户移出企业后，平台用户编辑接口不再接受该企业范围；企业删除时范围记录级联清理。

服务端在 `organizationService.authorize`、品牌范围解析和通知读取入口统一复核功能范围，页面隐藏不是授权依据。拒绝时返回 `ORGANIZATION_FEATURE_DISABLED`。

<a id="agent_quotas"></a>

## 代理商额度

代理商可配置三个独立上限：

- 企业额度：限制可作为 `tenant_admin` 管理的有效企业数，平台新增企业授权时实时校验；
- 品牌创建额度：按代理商成功创建品牌的审计记录累计，品牌写入前校验；
- 腾讯积分额度：限制代理商从企业余额池向品牌累计划拨的 `answerbit_points`，在余额事务内锁定代理商记录并校验，避免并发超额。

额度为 `null` 时不限，`0` 表示禁止，正整数表示累计上限。客户和管理员不使用这些字段；代理商切换为客户时额度自动清空。额度不替代企业订阅权益、企业余额或品牌余额，实际操作必须同时满足角色权限、目标企业功能范围、代理商额度和既有余额/权益约束。

企业管理员在成员设置中只绑定平台已创建的登录账号，不在企业端创建新凭证。选择 `tenant_admin` 时授予企业级角色；选择品牌管理员、编辑或查看角色时，系统自动使用当前企业唯一 Tencent BrandID 并写入 `brand_access`，页面不要求选择团队或手工输入 BrandID。成员在其加入的不同企业中可分别获得对应品牌范围；同一企业内对已绑定品牌重复授权时更新角色。移除范围、停用成员或移出企业即时影响后续授权，并保留审计记录。

## 生命周期规则

- 企业只由 Tencent BrandID 投影生成，平台增删改先操作腾讯品牌，名称跟随腾讯目录；本地创建和租户侧改名入口已弃用；
- 企业状态为 `suspended` 或 `closed` 时，不应继续提供正常租户业务访问；
- 成员状态只有 `active` 可参与授权；最后一个企业管理员不得被降级或移除；
- 用户停用是平台级动作，成员禁用是企业级动作，两者分别生效；
- 代理商有效状态要求账户未停用、当前时间不早于生效时间且早于到期时间；生效时间为空视为立即生效，到期时间为空视为长期有效；
- 代理商额度只限制新增企业授权、品牌创建和腾讯积分划拨，降低到小于已用量时保留历史数据但拒绝后续增量操作；
- 用户名不可变且全局唯一；旧环境中的无密码用户不计入系统已初始化状态；
- 敏感账号、成员和权限变化写入操作审计。
