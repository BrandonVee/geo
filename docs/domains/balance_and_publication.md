# 余额计费与发布履约

本文定义系统当前双余额账本、人工划拨、业务功能积分扣减与人民币发布履约规则。平台不存在在线充值、支付收单、支付回调或自动对账流程。

## 账本与单位

| 资产               | 数据值   | 单位     | 用途                                  |
| ------------------ | -------- | -------- | ------------------------------------- |
| `answerbit_points` | 非负整数 | 积分     | 腾讯 AnswerBit API 与异步文章能力调用 |
| `publication_cny`  | 非负整数 | 人民币分 | 媒体发布渠道订单                      |

每个企业为每种资产各有一个企业资金池；每个品牌可有同类品牌账户。两类资产不兑换、不混扣，展示层负责把人民币分格式化为元。

<a id="balance_invariants"></a>

## 人工划拨与账本不变量

资金只按以下路径流动：

```text
平台管理员 --grant--> 企业资金池 --allocate--> 品牌账户 --consume--> 业务
                                                        \--restore<-- 失败补偿
```

- 只有拥有 `platform.balance.manage` 的平台管理员可向企业资金池人工入账；
- 拥有 `balance.allocate` 的企业管理员或代理商可把企业余额划分到本企业品牌；划拨表单无需填写理由，接口未传或传空说明时自动记录“企业向品牌划拨”，保留操作人与金额流水；
- 代理商划拨 `answerbit_points` 时还受平台配置的腾讯积分累计额度约束；额度在同一余额事务内通过用户行锁校验，幂等重放不重复占用；
- 品牌角色只有 `balance.read`，不能自行划拨或调整余额；
- 所有金额必须为正整数，扣减通过条件更新保证余额不小于零；
- 每次 `grant`、`allocate`、`consume`、`restore` 都写不可变 `balance_transactions`；
- 登录用户发起的同步调用、文章生成和报告导出把用户 ID 写入扣减及失败返还流水；通知评估等系统任务不伪造操作用户，升级前的历史流水也允许用户字段为空；
- 幂等键在企业范围内唯一；余额事务先对“企业 + 幂等键”取得事务级 advisory lock，再查询原流水，因此并发重复请求也返回原结果，不重复改变余额或暴露唯一键冲突；
- 人工纠错通过新的 `adjust` 或补偿流水完成，不修改历史流水。

平台入账、手动扣减与企业到品牌划拨在同一事务内提交余额、不可变流水与操作审计；审计失败整体回滚。同键重放核对操作类型、账户、资产、金额、原因与操作者，内容不一致返回 `409 IDEMPOTENCY_CONFLICT`，成功重放不重复审计。

资产调整失败在原弹窗显示具体原因并保留输入。网络中断或服务端异常时，按企业和原幂等键只读核对流水，不以当前余额猜测成功。未查到流水仍保留原请求，可继续核对或显式按原内容和原键重试；未核实期间锁定输入并保留弹窗，避免改动金额生成第二笔调整。待核实记录在发送前按当前登录用户存入浏览器会话，刷新后恢复原内容并提供核对入口；浏览器无法暂存时不发送写入。核对读取使用与写入相同的企业级幂等锁，等待已持锁的余额事务结束。

企业划拨正常提交保持一次点击，校验整数积分及人民币分精度，不静默舍入；明确拒绝保留原表单。发送前按当前账号暂存原企业、品牌、资产、金额和幂等键，响应中断或服务端异常后只读核对本人原范围的划拨流水；刷新和切换企业仍保留原目标，不生成第二笔请求。未查到流水可继续核对或按原内容与原键重试，待核实期间不允许新划拨；读取失败保留金额及重试入口。核对与写入共享企业级幂等锁，等待已进入事务的划拨完成。成功写入与余额刷新失败分别呈现，新范围不显示旧余额，积分到期禁用积分划拨，人民币仍按服务有效期授权。

企业到品牌的划拨属于资产管理能力，不属于媒体发布流程。租户端在独立 `/dashboard/balances` 工作区展示企业资金池、品牌账户、划拨表单与企业资产流水；只有至少在一家企业拥有 `balance.allocate` 角色能力的用户显示该导航。媒体渠道、发布提交和发布订单分别使用 `/dashboard/publication/channels`、`/dashboard/publication/new` 与 `/dashboard/publication/orders`，这些页面不提供企业资金划拨入口。

平台资产目录分别展示企业资金池和当前映射品牌的积分、人民币余额，未建账户按零显示；关闭企业退出入账目录，但历史流水仍可查询。目录与跨企业流水要求 `platform.balance.manage`，企业管理查询不返回财务字段。划拨流水标注来源与目标账户；余额与分页查询规则见[企业资产目录](../architecture/platform_administration.md#asset_directory)。

<a id="point_usage"></a>

## 企业与品牌积分统计

租户工作台的“积分用量”读取本地 `answerbit_points` 账本，而不是共享 TeamID 的腾讯订阅或上游积分。企业管理员可以切换“企业整体”和“当前品牌”：企业整体展示企业资金池可分配余额、全部品牌可用余额合计、周期消耗、失败返还与净消耗，明细标注品牌；品牌视图只统计当前品牌。企业到品牌的划拨是内部转账，不计为业务消耗，人民币和管理员纠错也不混入积分功能统计。

品牌管理员、编辑者和查看者只能读取已授权品牌，不能请求企业整体或看到企业资金池。未指定品牌的 API 必须先通过企业角色授权；指定品牌时必须同时传内部团队绑定与品牌，并通过品牌授权。日期区间按北京时间闭合日期计算，类型筛选只改变明细与分页，不改变整个周期的消耗和返还汇总。余额、汇总和分页明细使用同一只读数据库快照，避免并发扣费使同次响应互相矛盾；相同时间的流水按 ID 稳定排序。页面切换范围后立即隐藏旧范围数据，失败时可以重试，不把旧品牌统计显示为新范围结果。共享 TeamID 的腾讯官方计量仅保留在平台管理“腾讯计量”。

## 年度积分与手动扣减

`organizations.points_expires_at` 是企业统一的积分到期日，覆盖企业资金池及品牌积分账户，新企业默认一年，管理员可按年续期。到期后禁止积分划拨和新积分功能，包括零价格的积分功能；不清零余额，续积分有效期可恢复使用。企业服务有效期优先；服务到期时，人民币发布与积分功能均停止。积分到期不影响服务有效企业的人民币业务，人民币余额不设置年度失效时间。普通入账不会自动修改任一有效期。旧企业的空到期日兼容原规则，由管理员补设。平台有效期编辑只提交已修改字段，单独续服务不会自动补设或延长积分期限；多人续期核对原日期，冲突不会覆盖最新期限，详见[企业服务有效期](./identity_and_access.md#enterprise_validity)。

平台管理员通过“资产与计费 → 入账 / 扣减”选择积分或人民币、企业资金池或品牌账户，填写数量及原因。`POST /v1/admin/balance-deductions` 只允许 `platform.balance.manage`；写入不可变 `adjust` 流水，标记 `admin_deduction`，保存操作者与扣减后余额，并写操作审计。条件更新防止负余额，企业级幂等锁使重复请求只扣一次，同键参数变化返回 409，余额不足返回 422；冻结或到期后仍允许管理员纠错扣减。退款仍返回原账户，不延长有效期。

## 腾讯能力积分

AnswerBit HTTP operation 是实现细节，接口调用本身一律不从本地账本扣积分。平台管理员按完整业务功能维护积分成本；同一功能无论内部调用一个接口、分页调用多个接口还是重试接口，只结算一次：

1. 业务入口读取 `feature_point_costs` 中的功能基础单价，并按操作用户的客户等级读取 `pricing_tier_rules.point_markup_bps`；最终扣减为基础积分乘以（1 + 积分加价率）后向上取整。0% 表示按基础积分计费，负加价率表示折扣，最低为 -100%；
2. 成本大于零时，从目标品牌 `answerbit_points` 账户按 `featureCode + referenceId` 幂等预扣；
3. 余额不足时终止整个功能，返回 `402 ANSWERBIT_POINTS_INSUFFICIENT`；
4. 功能成功则保留扣减；AnswerBit 调用日志仅负责观测，不参与结算；
5. 完整功能失败时按原扣减金额幂等返还；
6. API 查询、分页、轮询、重试、计量读取和平台目录同步均不单独扣积分；
7. 用户端会扣积分的主操作按钮展示按当前用户等级计算的积分消耗，但操作前不额外常驻预计消耗、失败返还或流程说明类静态提示；提交时浏览器附上已展示的积分报价，服务端按最新规则复核。不一致时返回 `409 FEATURE_PRICE_CHANGED`，不扣费、不调用上游，并刷新用户报价；一致时效果追踪立即结算，异步文章在任务中保存等级、基础积分、加价率和最终积分的价格快照，Worker 按快照扣费。用户主动点击具有独立外部副作用的确认操作后，二次确认层仍可展示本次影响。

效果追踪以本地追踪提交 ID 作为稳定 reference，提交、预扣及创建审计使用同一事务，返还与 failed/uncertain 状态更新同一事务；结果不确定也返还原预扣，但同键确认不会再次调用创建或扣款。已保存真实 ArticleID 的本地收尾失败继续恢复原提交，不退款；中断恢复后收到迟到成功时保留原 ArticleID 和已返还事实，不再次扣款。查看或刷新追踪目录和提交记录不计费，参见 [追踪流程](./geo_operations.md#article_tracking)。

当前已落地计费边界为 `ai_article_generation`（一次文章生成任务）和 `effect_tracking`（一次效果追踪创建）。视频、图文、Agent 分析、提问推荐、官网优化和商品推荐已进入功能价格目录，待对应业务功能落地后复用相同结算器。未公布具体成本的未来功能默认 0，需平台管理员配置后才开始扣减。平台不建立品牌套餐、赠送积分或品牌/席位加购规则；企业与品牌仍使用实际积分余额，但普通用户、铜牌代理、银牌代理和金牌代理可使用不同积分加价率。新规则默认分别为 30%、20%、15%、10%，与发布加价率初始值相同，但两项可独立调整。当前效果追踪基础价为 2 积分，四档均向上取整为 3 积分；这是接受的当前定价，不为拉开等级差异而自动提高基础价。

## 发布渠道与价格

平台管理员拥有 `platform.publication.manage`，负责创建人工渠道，并可对人工渠道和媒体发布聚合渠道分别设置平台上下架状态及四个客户等级的固定售价。媒体发布网站媒体与自媒体同步保留上游资源 ID、媒体类型、备注、案例、分类标题与履约指标，并把上游价格保存为独立采购成本、上游接单状态保存为独立状态；后续同步不得覆盖平台上下架、等级规则或渠道固定售价。

发布售价按以下优先级解析：渠道与客户等级存在固定价时使用固定价；否则媒体发布渠道按“采购成本 ×（1 + 等级加价率）”向上取整到人民币分；人工渠道沿用人工基础价。聚合渠道固定售价不得低于当前采购成本。租户发布页只返回操作用户等级对应的有效售价，可按媒体类型、分类标题、发布要求、预算、行业领域、综合门户、所在地区、入口级别、收录情况、链接类型、发稿速度、特殊行业、高级选项、价格、出稿率和平均出稿时间筛选排序；订单在同一扣款事务内再次解析用户等级售价并保存价格快照，不能信任浏览器价格。普通已登录用户只看到平台状态与上游状态均有效的渠道；任一状态下架后不能创建新订单，但历史订单保留价格快照和渠道关联。上游刷新失败时使用最近一次成功缓存，不把一次失败解释为渠道下架。

媒体发布账户自身的 `money` 与 `power_count` 是平台级采购余额，只允许拥有 `platform.publication.manage` 的管理员查看；它不参与租户余额账本，也不能替代品牌余额校验。聚合投稿在本地扣款前查询一次上游余额：明确低于所选渠道价格时返回 `FROG_PUBLICATION_BALANCE_INSUFFICIENT`，不创建订单也不扣品牌余额；查询超时或临时异常时不把未知状态误判成余额不足，仍由投稿接口作最终校验。若投稿接口随后明确拒绝，本地订单进入失败并返还原扣款。管理端余额查询异常不影响已有本地账本数据。

<a id="publication_state_machine"></a>

## 发布订单状态机

提交发布单时，系统校验品牌 `publication.create` 权限和有效渠道，在同一事务中从品牌 `publication_cny` 账户扣除渠道价格快照并创建 `submitted` 订单。渠道单价可以为零，免费订单正常创建与履约，但不写违反正金额约束的零元流水。

提交页允许从当前品牌文档库搜索并选择已定稿文章，来源可为腾讯 AI 生成、平台手工创作或外部导入。使用文档时按 `sourceDocumentId` 读取最新正文；服务端再次校验品牌范围、状态和非空正文。用户也可改用手工 HTML 正文。

```text
submitted -> processing -> published
    |             |
    +-----------> failed
    +-----------> cancelled
published --(聚合售后确认退款)--> failed
```

合法转换：

- `submitted` → `processing`、`failed`、`cancelled`；上游同步确认已发布且有有效结果链接时可直接进入 `published`；
- `processing` → `published`、`failed`、`cancelled`；
- `published` 通常为终态；仅聚合发布申诉后，上游明确返回已退稿且 `is_refund = 1` 时允许转为 `failed`；
- `failed`、`cancelled` 为终态；
- 进入 `published` 必须填写结果链接；
- 进入 `failed` 或 `cancelled` 时，按订单价格快照向原品牌返还一次人民币余额；
- 状态更新匹配旧状态，上游同步另匹配读取时版本时间；版本写入至少递增 1 毫秒并兼容数据库旧微秒时间戳。冲突返回 `409 PUBLICATION_ORDER_STATE_CONFLICT`。

聚合发布订单在本地按操作用户等级售价扣款和建单后，以本地订单 ID 作为上游 `third_id` 投稿。媒体发布账户余额预检只比较采购成本，不拿包含平台利润的客户售价与上游余额比较。上游明确接收后进入 `processing`；明确拒绝时进入 `failed` 并返还余额。超时、网络中断或 5xx 的结果可能已在上游生效，本地保留 `submitted` 和错误快照，不自动重投或退款，由后续状态查询或人工核对处理。同一本地幂等键重放不再次投稿，即使渠道、等级价格或配置变化也返回原订单；不可变身份字段不一致则返回 409。尚无上游订单号的结果不确定订单仍需人工核对，不会自动重投。Worker 每 5 分钟主动同步待履约与售后订单，当前品牌订单列表读取也会查询上游详情，把待安排、已安排、已发布、已退稿和售后中分别映射为本地状态；取消必须上游成功后才进入 `cancelled`。已发布订单提交申诉后继续查询售后状态，上游状态为售后中或退稿未退款时继续轮询，只有上游明确标记已退款时才转为 `failed` 并返还本地余额。

订单创建使用企业与幂等键的事务级 advisory lock，前端相同表单重试复用原键，防止并发重复下单；退款流水使用 `publication:<order_id>:restore` 唯一键防止重复返还。

聚合订单由上游同步驱动履约，管理员手工状态修改仅适用于人工渠道；取消终态与申诉状态均在调用上游前校验，已取消重试不再次请求上游。

## 权限与审计

| 操作                   | 权限                            |
| ---------------------- | ------------------------------- |
| 企业人工入账、积分单价 | `platform.balance.manage`       |
| 企业到品牌划拨         | `balance.allocate`              |
| 查看余额与流水         | `balance.read`                  |
| 发布渠道、全局订单履约 | `platform.publication.manage`   |
| 查看发布单             | `publication.read`              |
| 创建发布单             | `publication.create` + 品牌范围 |

人工入账、品牌划拨、积分单价、渠道和订单状态操作均写 `operation_logs`。余额列表与流水按企业隔离，品牌请求只返回对应品牌账户或订单。
