## 1. 文档说明

本项目不是自行调用大模型完成 GEO 检测，而是基于腾讯 AnswerBit OpenAPI 构建一个多租户 SaaS 平台。AnswerBit 负责品牌监控、问题采集、指标计算、大模型回答记录、引用分析和文章生成；本平台负责客户账户、权限、租户隔离、产品化界面、业务流程、报表和运营管理。

本文档以 AnswerBit 官方文档和 Apifox 项目 `AnswerBit`（项目 ID：`8802999`）为依据。2026-09-07 的接口快照包含 48 个已发布接口、48 个 request body 和 88 个数据模型，覆盖 7 个业务模块。

### 1.1 已确认决策

| 事项           | 决策                                           |
| -------------- | ---------------------------------------------- |
| AnswerBit 凭证 | 每个租户独立申请并维护自己的 API Key           |
| 团队绑定       | 一个租户可以绑定多个 AnswerBit `team_id`       |
| 普通接口超时   | 连接 3 秒、查询 15 秒、写操作 20 秒            |
| 文章生成       | 由本平台异步任务执行，不阻塞页面请求           |
| 商业化         | 建设本平台独立套餐、权益、额度、订单和支付系统 |

## 2. 产品定义

### 2.1 产品目标

为企业客户提供一个统一的 GEO 管理平台，使其能够：

1. 管理企业成员、品牌和竞品；
2. 配置需要持续监控的用户提问；
3. 查看品牌在不同 AI 平台中的提及率、平均排名和曝光效果分数；
4. 追溯大模型回答和引用来源；
5. 管理、生成和追踪用于 GEO 优化的文章；
6. 查看 AnswerBit 订阅、积分、额度和使用记录；
7. 通过平台自己的权限、报表、审计和通知功能完成团队协作；
8. 通过本平台套餐、额度、订单和支付完成商业化闭环。

### 2.2 核心价值

平台形成以下业务闭环：

```text
创建企业与品牌
    → 配置竞品和监控问题
    → AnswerBit 持续采集
    → 查看提及率、排名和引用来源
    → 生成或发布优化文章
    → 追踪文章引用效果
    → 复盘并调整监控与内容策略
```

### 2.3 核心指标定义

| 指标         | 产品含义                                   |
| ------------ | ------------------------------------------ |
| 品牌提及率   | 监控回答中出现目标品牌的比例               |
| 平均排名     | 品牌在已提及回答中的平均位置，数值越小越好 |
| 曝光效果分数 | AnswerBit 综合提及位置和次数计算的分数     |
| 监控问题数   | 当前品牌处于监控状态的问题数量             |
| 引用次数     | 大模型回答引用某个域名或文章的次数         |
| 积分消耗     | AnswerBit 对采集、生成等操作计算的资源消耗 |

品牌提及和来源引用是两个独立维度：品牌可能被提及但未引用官网，也可能网站内容被引用但回答中未出现品牌名称。

## 3. 用户与权限需求

### 3.1 用户类型

系统分为两个入口：

- **平台管理端**：供平台运营管理员使用；
- **客户工作台**：供企业管理员和企业用户使用。

为了匹配 AnswerBit 的团队及品牌权限，内部采用以下角色：

| 角色                      | 范围     | 主要能力                                                        |
| ------------------------- | -------- | --------------------------------------------------------------- |
| 平台管理员 `super_admin`  | 全平台   | 管理租户、账号、套餐、接口状态和审计日志                        |
| 企业管理员 `tenant_admin` | 企业     | 管理企业成员、多个 AnswerBit 团队连接、套餐订单和企业下全部品牌 |
| 品牌管理员 `brand_admin`  | 指定品牌 | 管理指定品牌、竞品、问题、文章和品牌成员                        |
| 品牌编辑者 `brand_editor` | 指定品牌 | 编辑问题、竞品和文章，查看全部品牌数据                          |
| 普通用户 `brand_viewer`   | 指定品牌 | 只读查看品牌指标、回答和文章效果                                |

产品界面可以将后三种统称为“用户”，但服务端必须保留品牌级权限差异。

### 3.2 权限矩阵

| 功能                    | 平台管理员 | 企业管理员 | 品牌管理员 | 品牌编辑者 | 普通用户 |

| 管理全部企业            |         是 |         否 |         否 |         否 |       否 |
| 管理本企业成员          |         是 |         是 |         否 |         否 |       否 |
| 配置 AnswerBit API Key  |         是 |         是 |         否 |         否 |       否 |
| 绑定 AnswerBit TeamID   |         是 |         是 |         否 |         否 |       否 |
| 查看企业全部品牌        |         是 |         是 |     按授权 |     按授权 |   按授权 |
| 编辑品牌资料            |         是 |         是 |         是 |         是 |       否 |
| 管理品牌成员            |         是 |         是 |         是 |         否 |       否 |
| 管理竞品                |         是 |         是 |         是 |         是 |       否 |

| 查看指标及回答记录      |         是 |         是 |         是 |         是 |       是 |
| 生成、追踪文章          |         是 |         是 |         是 |         是 |       否 |

### 3.3 权限规则

1. 前端隐藏按钮不能代替服务端权限校验。
2. 每次请求必须同时校验用户、企业、品牌授权和操作权限。
3. 用户可以加入多个企业，并在不同企业或品牌拥有不同角色。
4. 本平台授予的权限不得超过租户自有 AnswerBit API Key 已开通的团队、品牌和读写范围。
5. 平台管理员跨租户操作必须记录审计日志。
6. 禁用用户后，其全部有效 Session 应立即失效。
7. 品牌授权必须关联到具体 AnswerBit 团队绑定，不能只依赖 `brand_id` 字符串。

## 4. AnswerBit 接入约束

### 4.1 基础约束

| 项目         | 要求                                            |
| ------------ | ----------------------------------------------- |
| Base URL     | `https://answerbit.qq.com`                      |
| 鉴权 Header  | `X-API-Key: API_KEY`                            |
| API Key 获取 | 通过 AnswerBit 服务人员申请                     |
| 凭证归属     | 每个租户独立申请；平台不跨租户共用 API Key      |
| 接口方法     | 当前 48 个接口全部使用 POST                     |
| 团队标识     | `team_id`，由 AnswerBit 提供或从控制台 URL 获取 |
| 品牌标识     | `brand_id`，由 AnswerBit 提供、查询或创建后取得 |
| 权限边界     | 由 API Key 申请时开通的团队、品牌和读写能力决定 |
| 通用响应     | `{ "code": 0, "msg": "success", "data": ... }`  |

### 4.2 接入原则

1. 浏览器不能直接请求 AnswerBit，所有调用必须经过平台服务端。
2. API Key 必须加密保存，接口和日志只能展示掩码。
3. 平台为每次调用生成 `requestId`，并记录操作、耗时、结果和错误码。
4. AnswerBit 返回的 `code` 是业务结果依据，不能只判断 HTTP 状态码。
5. 查询类接口可针对网络错误有限重试；写接口仅在确认幂等时重试。
6. 对 AnswerBit 返回字段进行运行时校验，避免外部字段变化直接破坏页面。
7. 保存本地 ID 与 `team_id`、`brand_id`、`competitor_id`、`prompt_id`、`article_id` 的映射。
8. 一个租户可以添加多个 API Key 连接，每个连接可以绑定一个或多个其有权访问的 `team_id`。
9. 同一租户内 `(organization_id, team_id)` 必须唯一；TeamID 绑定必须记录连接、状态和末次验证时间。

### 4.3 数据归属

| 数据                               | 权威来源                                  |
| ---------------------------------- | ----------------------------------------- |
| 用户、登录 Session                 | 本平台                                    |
| 企业、成员和权限                   | 本平台                                    |
| AnswerBit API Key 和授权映射       | 本平台加密存储                            |
| 品牌、竞品、监控问题               | AnswerBit，本地保存必要映射和缓存         |
| 提及率、排名、分数、回答、引用     | AnswerBit                                 |
| AnswerBit 套餐、积分和额度         | AnswerBit，只读展示                       |
| 本平台套餐、订单和支付             | 本平台，不能与 AnswerBit 计量混为一套数据 |
| 本平台套餐权益、额度占用和用量流水 | 本平台                                    |
| 保存的筛选条件、报表和通知         | 本平台                                    |
| 操作审计                           | 本平台                                    |

## 6. 功能需求

### 6.1 账户与企业

#### FR-AUTH-001 用户登录

- 用户使用中国大陆手机号和短信验证码注册或登录，不设置固定密码。
- 手机号在系统内唯一，入库前统一转换为 E.164 格式。
- 验证码为 6 位数字，5 分钟有效，单个验证码最多允许验证 3 次。
- 同一手机号 60 秒内只能发送一次；单手机号、单 IP 和单设备均设置小时及日级限额。
- 连续触发发送或验证失败阈值时要求通过人机验证。
- 短信通过腾讯云短信 `SendSms` 发送，记录发送结果和腾讯请求 ID，但不记录验证码明文。
- 用户可以登录、退出和修改基础资料及绑定手机号。
- 登录成功后进入上次访问的企业；没有企业时进入加入/创建企业流程。
- 被禁用用户不能继续使用旧 Session。

#### FR-TENANT-001 企业管理

- 平台管理员可以创建、冻结和恢复企业。
- 企业管理员可以维护企业名称和企业成员。
- 企业必须至少绑定一个有效的 AnswerBit `team_id` 后才能使用 GEO 功能。
- 一个企业可以绑定多个 AnswerBit 团队，并设置一个默认团队。
- 切换团队后，品牌、计量和概览数据必须随 TeamID 同步切换。

#### FR-TENANT-002 成员与品牌授权

- 企业管理员可以邀请和移除成员。
- 可以为成员配置企业管理员或品牌级角色。
- 品牌级用户只能看到被授权的品牌。

### 6.2 AnswerBit 连接

#### FR-CONN-001 配置连接

- 每个租户使用自己向 AnswerBit 申请的 API Key，平台不提供跨租户共享密钥。
- 企业管理员先录入 API Key，再添加一个或多个 `team_id`。
- 每个 TeamID 保存前调用品牌列表接口验证凭证及团队访问权。
- 一个租户可以保存多个 AnswerBit 连接，以兼容不同 TeamID 分属不同 API Key 的情况。
- 相同 API Key 不重复保存；一个连接可供该租户下多个 TeamID 绑定复用。
- 页面只展示 API Key 掩码、连接状态和末次验证时间。
- 轮换 API Key 时先验证新密钥，再原子切换；旧密钥切换成功后停止使用。

#### FR-CONN-002 TeamID 管理

- 企业管理员可以新增、验证、设置默认、禁用和解绑 TeamID。
- 解绑前检查品牌授权、未完成生成任务和报表依赖；存在依赖时要求先迁移或确认终止。
- TeamID 页面展示连接状态、品牌数量、末次同步时间和末次错误。
- 普通用户只看到其品牌授权覆盖的 TeamID，不显示 API Key 信息。

#### FR-CONN-003 连接异常

- 对无权限、Key 失效、限流、网络超时和 AnswerBit 服务异常显示不同提示。
- 管理员可以查看关联 `requestId`，普通用户不展示内部错误细节。
- 连接连续失败时在管理端显示告警。

### 6.3 品牌与竞品

对应 AnswerBit 9 个接口。

#### FR-BRAND-001 品牌列表

- 获取当前 AnswerBit 团队下的全部品牌。
- 根据本地品牌授权过滤普通用户可见范围。
- 支持选择当前品牌，并在后续页面保持选择状态。

#### FR-BRAND-002 创建品牌

- 支持仅创建品牌。
- 支持通过组合接口一次创建团队/品牌、初始化竞品和监控问题。
- 品牌名称必填；别名、官网、描述、备注和 Logo 可选。
- Logo 类型和大小遵循 AnswerBit 限制，最大 2MB。
- 创建成功后保存本地企业和 AnswerBit 品牌 ID 映射。

#### FR-BRAND-003 编辑品牌

- 支持编辑品牌名称、别名、官网、描述、备注和官网自动追踪开关。
- AnswerBit 品牌更新接口具有全量更新语义，平台提交前必须合并现有值，避免未传字段被置空。
- Logo 使用独立接口更新。

#### FR-COMP-001 竞品管理

- 查看、新增、编辑和删除当前品牌竞品。
- 删除前进行二次确认。
- 竞品编辑接口按全量字段提交，避免未传字段被置空。

### 6.4 监控问题与分类

对应 AnswerBit 11 个接口。

#### FR-PROMPT-001 分类管理

- 查看、新建、更新和删除问题分类。
- 删除分类前提示其关联问题可能受到的影响。
- 支持将问题移动到其他分类。

#### FR-PROMPT-002 问题管理

- 支持创建、编辑、启用、禁用和删除问题。
- 支持批量创建和批量删除。
- 更新问题时遵循局部更新语义；空字符串不能作为有效问题内容。
- 支持按分类、日期、标签和关键字筛选。

#### FR-PROMPT-003 分组列表

- 默认按分类展示问题数量、提及率、平均排名、曝光分数和趋势。
- 未指定日期时使用 AnswerBit 默认的过去 7 天范围。
- 自定义日期必须同时提交开始日期和结束日期。
- 支持分页和展开查看分类下的问题。

### 6.5 GEO 概览与分析

对应 AnswerBit 10 个接口。

#### FR-DASH-001 全局筛选

概览页统一支持：

- 日期范围；
- AI 平台；
- 问题分类；
- 问题标签；
- 竞品。

筛选项变更后，所有指标卡、趋势图和排行榜保持一致。可筛选平台从 AnswerBit 接口动态获取，不在前端写死。

#### FR-DASH-002 指标卡

- 展示品牌提及率、平均排名、曝光效果分数和监控问题数。
- 展示相对上一同等长度周期的变化值。
- 平均排名明确提示“数值越小越好”。

#### FR-DASH-003 品牌趋势

- 支持切换提及率、平均排名和曝光效果分数。
- 展示当前品牌逐日数据。
- 可以选择竞品并展示同期趋势。

#### FR-DASH-004 竞品对比

- 对比当前品牌及竞品的提及率、平均排名和曝光效果分数。
- 当前品牌由 AnswerBit 返回的 `competitor_id = "0"` 标识。

#### FR-DASH-005 分类指标

- 按问题分类展示提及率、平均排名、曝光效果分数和变化值。
- 支持从分类下钻至问题列表。

#### FR-DASH-006 引用排行

- 展示引用域名排行，区分是否为品牌官网域名。
- 展示引用文章排行，包括标题、URL、域名、引用次数、来源和追踪文章 ID。
- 支持关键字搜索、分页和当前筛选条件。

### 6.6 大模型回答记录

对应 AnswerBit 2 个接口。

#### FR-ANSWER-001 回答列表

- 按问题展示 AnswerBit 已采集的大模型回答。
- 支持品牌、日期、平台、分类、标签、提及状态和关键字筛选。
- 列表至少展示问题、平台、提及状态、曝光分数和评估时间。

#### FR-ANSWER-002 回答详情

- 展示完整回答内容和 AnswerBit 返回的元信息。
- 高亮品牌名称和别名。
- 展示平台、时间、地区、语言和引用来源。
- AnswerBit 返回 `pic` 时展示采集图片或截图；字段为空时不显示截图区域。
- 页面文案使用“AnswerBit 采集结果”，不得暗示由本平台直接调用模型获得。

### 6.7 文章管理和优化

对应 AnswerBit 7 个接口，其中文章管理 4 个，AI 文章生成 3 个。

#### FR-ARTICLE-001 追踪文章

- 获取团队可用标签。
- 支持录入文章标题、一个或多个公开发布 URL、标签和语言。
- 支持的语言使用 AnswerBit 文档中的 BCP 47 语言码。
- 展示文章列表、状态、来源、模板类型、引用次数、趋势和发布平台。
- 文章列表使用 AnswerBit `scroll_id` 游标翻页。

#### FR-ARTICLE-002 文章追踪详情

- 展示同一文章的多个发布链接。
- 展示各 AI 平台的引用次数和每日趋势。
- 展示产生引用的问题、所属分类和引用次数。

#### FR-ARTICLE-003 文章生成

- 获取 AnswerBit 可用文章模板。
- 用户选择目标问题、模板和接口要求的生成参数后提交生成任务。
- 页面请求只创建本地任务并返回 `job_id`，不等待 AnswerBit 生成完成。
- 任务状态包括 `queued`、`running`、`succeeded`、`failed`、`cancelled`。
- Worker 调用 AnswerBit `/geo/article/create`，成功后通过 `/geo/article/get` 获取文章内容并保存结果引用。
- 前端通过轮询获取状态；首期不要求 WebSocket。
- 相同租户、品牌和幂等键不能重复创建有效生成任务。
- 单任务执行超时 120 秒；超时后先查询或核对外部结果，再决定是否重试，防止重复扣除积分。
- 展示文章生成状态、失败原因、生成结果和文章内容。
- 文章生成可能消耗 AnswerBit 积分，提交前显示风险提示。
- 生成内容由用户审核后再发布，本平台不自动宣称效果保证。

### 6.8 AnswerBit 计量中心

对应 AnswerBit 9 个只读接口。

#### FR-METER-001 用量与订阅

- 展示当前计费周期用量。
- 展示 AnswerBit 订阅信息。
- 展示积分总量、可用量、冻结量等接口返回状态。

#### FR-METER-002 积分分析

- 展示积分消耗占比和趋势。
- 展示品牌积分消耗排行。
- 支持按当前周期或指定时间范围查询。

#### FR-METER-003 操作记录

- 展示积分流水、订阅日志和配额调整记录。
- 支持分页、时间和关键字筛选。
- 明确标识冻结中与已确认的积分流水。

AnswerBit 计量信息仅用于显示上游资源消耗，不直接等同于本平台向客户计费的数据。

### 6.9 本平台套餐、额度、订单与支付

#### FR-BILLING-001 套餐管理

- 平台管理员可以配置套餐名称、价格、计费周期、上下架状态和版本。
- 套餐权益至少支持：企业成员数、AnswerBit TeamID 数、品牌数、文章生成任务数、报表导出数和数据保存期限。
- 套餐发布后生成不可变版本；修改价格或权益时创建新版本，历史订单继续引用旧版本。
- 支持免费版、按月套餐和按年套餐；自动续费不作为首期要求。

#### FR-BILLING-002 额度与权益

- 每个企业拥有一份本平台订阅和权益快照。
- 额度使用采用不可变流水记录，并维护可查询余额。
- 生成文章等操作先预占额度，成功后确认，失败或取消后释放。
- 本平台额度和 AnswerBit 积分必须分别展示。
- 一项操作同时受两侧限制时，有效可用能力取本平台权益和 AnswerBit 上游可用能力的较小值。
- 管理员人工调整额度必须填写原因并写入审计日志。

#### FR-BILLING-003 创建订单

- 企业管理员选择套餐后创建订单。
- 订单保存套餐版本、购买周期、原价、优惠、应付金额和货币，不在支付回调时重新计算价格。
- 商户订单号全局唯一，重复提交相同幂等键返回原订单。
- 未支付订单在有效期结束后关闭；重新购买创建新订单号。

订单状态：

```text
pending → paid → fulfilled
pending → closed
paid → refunding → refunded
```

#### FR-BILLING-004 微信支付

- 首期桌面端使用微信支付 API v3 Native，下单后展示 `code_url` 二维码。
- 支付完成以服务端验签后的支付通知及主动查单结果为准，不以浏览器跳转为准。
- 支付通知必须验签、解密、核对商户订单号、商户号、币种和金额。
- 同一支付通知可以重复到达，系统必须幂等处理。
- 支付成功、订单置为已支付、开通订阅和写入支付流水在同一数据库事务中完成。
- 回调处理成功返回微信要求的成功状态；处理失败保留日志并由查单任务补偿。
- 支付 Provider 保留统一接口，支付宝作为 P2 扩展。

#### FR-BILLING-005 订单与支付记录

- 企业管理员查看本企业订单、支付状态、购买套餐和开通结果。
- 平台管理员按企业、订单号、支付渠道、状态和日期查询订单。
- 支付敏感字段、证书和密钥不出现在前端及普通日志中。
- 退款首期由平台管理员发起，退款金额不得超过实付金额。

### 6.10 平台附加功能

#### FR-EXT-001 保存视图

## 8. 关键业务流程

### 8.1 企业开通

```text
平台管理员创建企业
    → 企业管理员接受邀请
    → 录入租户自有 AnswerBit API Key
    → 添加一个或多个 team_id
    → 服务端逐个调用 /geo/query/brand 验证
    → 同步各团队品牌列表
    → 配置成员品牌权限
    → 进入工作台
```

### 8.2 新品牌初始化

```text
填写品牌信息
    → 添加竞品
    → 添加初始监控问题
    → 调用 /geo/brand/bundle/create
    → 保存 brand_id 等映射
    → 配置品牌成员
    → 等待 AnswerBit 产生监控数据
```

AnswerBit 数据从品牌创建后开始采集，不提供创建前历史数据。产品界面必须在空状态中说明这一点。

### 8.3 日常分析

```text
选择品牌和时间范围
    → 查看核心指标
    → 对比竞品及平台
    → 下钻问题或回答
    → 查看引用域名和文章
    → 保存视图或导出报表
```

### 8.4 内容优化

```text
选择表现较差的问题
    → 查看高引用来源
    → 选择 AnswerBit 文章模板
    → 创建异步生成任务
    → Worker 调用 AnswerBit 并记录结果
    → 用户人工审核文章
    → 在公开渠道发布
    → 回填发布链接并开始追踪
    → 后续查看引用效果
```

页面需要提示：文章发布后通常不能立即看到引用效果，且不保证一定被引用。

### 8.5 套餐购买

```text
企业管理员选择套餐版本
    → 服务端计算并固化订单金额
    → 创建待支付订单
    → 调用微信 Native 下单
    → 页面展示支付二维码并轮询订单

    → 事务内更新订单、支付流水、订阅和权益
    → 页面展示开通成功
```

浏览器轮询仅用于刷新显示；支付成功的事实来源是服务端支付通知或服务端主动查单。

## 10. 非功能需求

### 10.1 安全

- API Key 仅在服务端解密和使用；
- 敏感操作进行权限校验和审计；
- 租户业务查询强制携带企业 ID；
- 品牌查询额外校验品牌授权；
- 日志不得记录完整 API Key、Session 或敏感请求字段；
- 短信验证码不得明文落库或写入日志，并对手机号、IP、设备进行限流；
- 支付通知必须验签、解密、金额核对和幂等处理；
- 防止水平越权、重放、CSRF 和批量导出越权。

### 10.2 性能

- 不依赖 AnswerBit 的平台接口 P95 目标小于 500ms；
- AnswerBit 普通调用采用连接超时 3 秒、查询总超时 15 秒、写操作总超时 20 秒；
- 文章生成 Worker 单次调用超时 120 秒，任务最大运行时间 5 分钟；
- 短信发送和支付下单总超时 10 秒，超时后允许用户重试或由服务端查单；
- 多图表页面由服务端聚合并限制并发，避免浏览器同时发起大量上游请求；
- 对日更或低频变化的指标允许短时间缓存；
- 列表必须分页，禁止一次拉取全部回答或流水。

### 10.3 可用性

- AnswerBit 暂时异常时，平台登录、权限和管理后台仍可使用；
- 已缓存数据标注最后更新时间；
- 外部写操作结果不确定时禁止盲目重试，并进入人工核对状态；
- 支付通知遗漏时通过主动查单任务补偿；
- 异步任务进程重启后可以重新领取未完成任务；
- 数据库每日备份，正式上线前完成恢复演练。

### 10.4 可观测性

- 全链路使用 `requestId`；
- 监控 AnswerBit 调用成功率、耗时、业务错误码和超时率；
- 记录企业和接口维度调用量；
- 对连接连续失败、权限异常和积分不足触发告警。

## 13. 验收标准

### 13.1 权限验收

- 普通用户不能进入平台管理端和企业设置页面；
- 品牌用户不能读取未授权品牌数据；
- 品牌编辑者可以编辑业务数据，但不能管理企业成员和 API Key；
- 企业管理员可以管理本企业，但不能读取其他企业；
- 平台管理员跨企业操作有完整审计记录。

### 13.2 AnswerBit 接入验收

- 使用 `X-API-Key` 由服务端成功调用 AnswerBit；
- 每个租户使用自己的 API Key，密钥不会被其他租户复用；
- 一个租户可以验证并绑定多个 `team_id`，不同 TeamID 的品牌和计量数据正确隔离；
- 48 个接口均在适配层有明确映射，P0 接口完成联调；
- AnswerBit `code != 0` 时平台返回统一错误；
- API Key 不出现在浏览器、日志和错误响应中；
- 外部写操作不会因为自动重试产生重复数据。

### 13.3 业务验收

- 企业管理员能够完成品牌、竞品和监控问题初始化；
- 用户能够查看概览、趋势、竞品对比和回答详情；
- 用户能够查看引用域名和文章排行；
- 有权限用户能够生成和追踪文章；
- 文章生成由异步任务执行，页面请求不会等待 AnswerBit 完成；
- 企业管理员能够查看 AnswerBit 订阅、积分和用量；
- 用户可以通过手机号验证码登录，短信发送和验证码校验具备防刷限制；
- 企业管理员可以购买本平台套餐，微信支付回调重复到达不会重复开通权益；
- 本平台额度、AnswerBit 积分和订单金额分别计算并清晰展示；
- 页面具备加载、空数据、无权限、未连接和外部服务异常状态。

## 14. 推荐默认值与外部确认项

### 14.1 已采用的默认值

1. **AnswerBit 调用并发**：在官方限额确认前，每个连接默认最多并发 3 个请求，并允许后台配置。
2. **数据更新**：当前按主动查询处理，不依赖 AnswerBit Webhook；以后确认有回调能力再接入。
3. **回答截图**：`/geo/task/detail/get` 已定义 `pic` 字段，有值时展示，无值时隐藏。
4. **TeamID 数量**：平台不写死 AnswerBit 的上限，由本平台套餐权益和 AnswerBit Key 实际权限共同限制。
5. **支付方式**：首期使用平台主体的微信直连商户号和 Native 扫码支付，不做自动续费。
6. **订单有效期**：默认 30 分钟；过期订单关闭，重新支付需创建新订单。
7. **退款方式**：首期只允许平台管理员人工发起，不提供用户自助退款。
8. **套餐变更**：升级立即创建差额订单并生效；降级在当前周期结束后生效。
9. **报表通知**：P1 先做 CSV 和站内通知；PDF、邮件、企业微信通知后续实现。
10. **开票能力**：不作为首期功能，但订单和企业信息预留开票字段。
11. **缓存与文件**：AnswerBit 指标短缓存 5 分钟，导出文件默认保留 7 天。
12. **日志保存**：接口调用日志和审计日志默认保留 180 天；支付及订单数据按财务合规要求长期保存，不提供普通物理删除。

### 14.2 需要外部确认或业务输入

1. AnswerBit API Key 的正式频率限制、日调用上限和并发限制。
2. AnswerBit 同一 API Key 可访问 TeamID 的数量上限。
3. AnswerBit 文章生成超时后的查询、请求 ID 或结果核对机制。
4. 本平台首发套餐名称、价格及具体额度；这些参数存入套餐版本，不写死在代码中。
5. 微信支付商户号、AppID、API v3 密钥和平台公钥的正式生产配置。
6. 最终退款条款、客户服务条款和数据合规保存期限。
