# AI流量推荐官GEO聚合服务平台｜开发与运营总体方案 V1.0

> 归档声明：本文是早期业务规划，不代表当前已实现范围。当前系统设计从[工程文档入口](../index.md)查阅，余额与发布规则以[余额计费与发布履约](../domains/balance_and_publication.md)为准。

## 一、项目定位

本项目不是单一GEO工具，也不是单一媒体发稿平台，而是以腾讯GEO技术平台为底层AI能力，接入现成的新媒体、自媒体、新闻媒体、传统媒体、B2B媒体和视频媒体资源，形成面向平台方、分层代理商及品牌客户的GEO聚合服务与履约平台。

平台完成五类能力整合：品牌诊断与监测、内容生成、媒体发布、代理销售管理、用量与财务核算。

## 二、已确认的业务口径

1. 腾讯提供底层GEO能力和API，平台建设自己的业务、账户、权限、价格、Token和媒体余额体系。
2. 业务角色分为总运营中心、代理商、品牌客户；技术实现可以使用统一账户体系加角色权限，不必建设三套系统。
3. 代理商分省代、市代、区代等层级，不同层级使用不同的Token采购价、媒体发布价及其他服务价格。
4. 代理商可以自行发展客户。所谓“开户”，实质是新增品牌、创建或邀请品牌成员，并把用户加入对应品牌或团队。
5. 品牌客户为单品牌使用方，只能查看和使用自己获授权的品牌。
6. 腾讯当前口径为：一个企业激活一个套餐，对应一个团队，团队内可以添加多个品牌。
7. 腾讯支持追加采购积分。平台自行实现单密钥或多密钥接入、总量调度、额度记录和预警。
8. 不依赖腾讯API返回Token消耗；平台按自身业务调用与扣减规则记录逻辑Token账。腾讯侧总量不足时触发预警并人工追加采购。
9. 账户分为两套：`Token`用于腾讯GEO能力；`余额`用于媒体发布。
10. 平台不建设在线充值和自动支付闭环。用户通过线下转账或对公付款，财务审核后由平台人工增加Token或余额。
11. 腾讯套餐到期时未消耗额度失效，不结转；平台套餐与客户协议中必须明确有效期。
12. 平台采购成本、底层供应商价和内部利润仅总运营中心可见；代理商只见本层采购价，品牌客户只见市场销售价或代理商为其配置的终端价。

## 三、平台总体架构

### 3.1 能力层

- 腾讯GEO：品牌诊断、监测、文章生成、视频生成及其他开放API能力。
- 媒体资源：新闻媒体、自媒体、新媒体、B2B媒体、视频媒体等发布渠道。
- 平台自有能力：用户权限、品牌管理、代理层级、价格体系、Token账、余额账、订单、审核、预警和报表。

### 3.2 角色与数据权限

| 角色       | 管理范围                   | 可见价格                       | 关键操作                                         |
| ---------- | -------------------------- | ------------------------------ | ------------------------------------------------ |
| 总运营中心 | 全平台、全部代理与品牌     | 平台成本价、各级代理价、市场价 | 配置能力、代理层级、价格、额度、审核、预警、对账 |
| 省代       | 自身及授权辖区内账户和品牌 | 省代采购价、下级供货价         | 创建下级代理、添加品牌、分配额度、运营服务       |
| 市代       | 自身及授权辖区内账户和品牌 | 市代采购价、下级供货价         | 创建授权下级、添加品牌、分配额度、运营服务       |
| 区代       | 自身客户与品牌             | 区代采购价、客户销售价         | 添加品牌、邀请客户、配置额度、运营服务           |
| 品牌客户   | 单一获授权品牌             | 市场价或代理配置价             | 使用GEO能力、提交发布、查看记录和结果            |

代理层级必须可配置，不能把省、市、区写死在代码里；平台可决定某一层是否有发展下级权限。

### 3.3 品牌与团队关系

平台侧采用“代理组织—品牌—品牌成员”的模型：

- 一个代理组织可以管理多个品牌；
- 一个品牌可以拥有多个成员，但成员权限只在该品牌内生效；
- 品牌客户默认只能加入一个品牌；如同一主体确需多品牌，由平台或上级代理另行授权；
- 腾讯侧一个企业套餐对应一个团队，团队中建立多个品牌；
- 平台保存自有品牌ID与腾讯品牌ID映射，避免业务层直接依赖腾讯页面结构。

## 四、Token与余额体系

### 4.1 Token账户

Token用于腾讯GEO能力调用。平台维护三本逻辑账：

- 平台Token总账：采购、追加、有效期、已分配、已消耗、可用量；
- 代理Token分账：获得额度、下发额度、自用消耗、剩余额度、到期日；
- 品牌Token分账：获得额度、具体功能消耗、剩余额度、到期日。

Token扣减必须由平台在发起业务调用前后落账，并使用幂等业务流水号防止重复扣减。若外部调用失败，应回滚或冲正。

Token有效期按逐级继承原则管理：平台采购Token记录上游到期日；平台分配给代理商时必须设置到期日，且不得晚于对应上游Token的到期日；代理商再分配给品牌时同样必须设置到期日，且不得晚于代理商所持额度的到期日。同一账户存在多批不同到期日Token时，默认优先消耗最早到期批次，过期额度自动冻结并记录失效流水，不得继续下发或使用。

预警至少包括：剩余20%、10%、5%，预计七日内耗尽，平台/代理/品牌Token分别在30日、15日、7日、3日、1日内到期，以及调用异常连续发生。

### 4.2 媒体余额账户

余额只用于媒体发布：

1. 代理商或品牌客户线下付款；
2. 提交充值申请和付款凭证；
3. 财务或平台运营人员审核；
4. 后台人工增加余额并生成不可删除的入账流水；
5. 用户提交媒体发布订单；
6. 按其身份对应价格冻结、扣减或退款。

系统不提供支付接口、银行卡支付或第三方在线充值入口。所谓“充值”均指线下收款后的人工入账。

### 4.3 价格体系

每项商品或能力保存：平台成本价、省代价、市代价、区代价、市场指导价。前端根据登录角色只返回其可见价格，成本字段不能仅依靠页面隐藏，API也不得返回。

Token价格、媒体价格及其他服务价格分别维护，支持按单项、套餐、客户或代理层级覆盖，并保留生效时间和历史版本。

## 五、核心业务流程

### 流程A：代理商开通

平台招商审核 → 确定代理层级和区域 → 签约及线下付款 → 平台创建代理组织 → 配置价格与权限 → 分配初始Token/余额 → 培训上线。

### 流程B：代理商发展品牌客户

代理商新增品牌 → 填写品牌资料 → 邀请客户成员 → 配置权限与额度 → 客户进入单品牌工作台 → 开始诊断、生成和发布。

### 流程C：GEO业务执行

品牌建档 → 关键词与问题库 → GEO诊断/监测 → 内容策略 → 文章或视频生成 → 审核 → 媒体发布 → 收录与推荐监测 → 复盘优化。

### 流程D：媒体发布

选媒体 → 查看本角色价格 → 创建订单 → 校验并冻结余额 → 运营审核 → 对接外部发布 → 回填发布结果 → 成功扣款或失败退款。

## 六、产品模块

### 总运营后台

- 代理商和区域层级管理
- 角色、菜单、数据和操作权限
- 品牌、团队及腾讯映射管理
- 腾讯密钥、套餐、有效期和容量管理
- Token总账、分配、回收、冲正和预警
- 媒体资源、成本价、分层销售价和上下架
- 线下收款申请、审核、人工入账和财务流水
- 发布订单、异常、退款、对账和经营报表
- 审计日志与敏感操作复核

### 代理商后台

- 下级代理（按授权开放）
- 多品牌和客户成员管理
- Token与余额分配
- 本层价格和客户报价
- GEO任务与媒体发布订单
- 客户消耗、订单、收益和对账报表
- 培训资料、运营SOP和工单支持

### 品牌客户工作台

- 单品牌资料和素材库
- GEO诊断、监测、关键词与问题库
- 文章、短视频等内容生成
- 媒体选择、发布下单与结果查看
- Token、余额、消费流水和到期提醒
- 效果报表与运营服务入口

## 七、开发阶段

### 第一阶段：规则验证版

优先验证一个完整闭环：平台创建代理 → 代理添加品牌 → 分配Token/余额 → 品牌使用GEO能力 → 提交媒体发布 → 返回结果 → 完成扣费与对账。

暂不开发复杂省市区地图、在线支付、自动结算和高度定制化报表。

### 第二阶段：代理运营版

上线可配置代理层级、下级代理、差异化价格、收益报表、额度预警、培训资料和工单体系。

### 第三阶段：规模化运营版

完善自动化对账、套餐产品化、代理考核、区域保护、线索分配、交付SOP、经营驾驶舱和风险监控。

## 八、未来运营方案

### 8.1 商业产品结构

- 工具型：系统使用权＋Token套餐；
- 发布型：媒体余额充值＋单次发布服务；
- 服务型：诊断、策略、培训、陪跑和代运营；
- 结果型：在合同与合规允许的情况下，根据真实交付目标设计项目服务费或增量激励。

平台重点不应停留在卖账号，而应通过“工具＋培训＋陪跑＋代运营”提高续费、复购和客户结果。

### 8.2 代理商运营机制

- 准入：企业资质、区域能力、客户资源、服务团队和合规承诺；
- 启动：产品培训、GEO方法论、销售话术、首个客户陪跑；
- 经营：月度目标、活跃品牌数、Token消耗、媒体发布额、续费率和客户结果；
- 支持：统一物料、案例、报价工具、运营SOP和疑难工单；
- 升降级：依据真实业务量和服务质量调整价格等级与发展下级权限；
- 退出：停用新增权限，完成客户、余额、数据和合同交接。

省代、市代、区代只作为商业等级和权限标签，必须避免仅靠发展下级获得收益。收入应以真实系统服务、媒体发布和客户运营交付为基础。

### 8.3 总运营中心职责

- 对接腾讯及媒体供应商，维护能力稳定性和采购成本；
- 制定价格、套餐、区域和代理政策；
- 统一品牌诊断、内容、发布和复盘方法论；
- 培训代理并陪跑首批项目；
- 审核充值、异常订单和敏感操作；
- 建立成功案例、续费机制和经营数据看板；
- 监控未交付、额度不足、价格倒挂、客户投诉与合规风险。

## 九、关键验收指标

- 权限隔离：任何代理和品牌不能查看未授权数据或成本价；
- 账务准确：Token和余额每笔变化均有流水，汇总与明细一致；
- 调用可靠：失败调用不重复扣费，可冲正、可追溯；
- 价格正确：同一媒体或能力按不同角色返回正确价格；
- 业务闭环：首个代理与首个品牌能够完成从开通到发布结果的全过程；
- 运营可用：运营人员无需改数据库即可开户、配价、加额、退款和处理异常。

## 十、仍需补充的外部事实

1. 腾讯“企业—空间—团队—品牌”的正式文字说明及接口字段。
2. 单密钥或多密钥的最终对接方式、并发限制与接口异常规则。
3. 腾讯各功能实际Token扣减标准及套餐有效期规则。
4. 代理层级是否允许跨区域、越级发展或同一区域多代理。
5. 余额充值审批人、财务凭证要求与退款权限。

这些内容不阻塞产品框架设计，但在对应功能开发前必须形成书面规则。
